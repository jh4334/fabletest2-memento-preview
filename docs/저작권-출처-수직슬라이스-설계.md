# 저작권·출처 수직 슬라이스 설계

> **상태:** 구현 전 플레이 계약 v1<br>
> **대상:** 「마음의 문」 메멘토 시간선 체험<br>
> **플레이 길이:** 첫 조작부터 결과 카드까지 30~40분<br>
> **범위:** 다섯 과거/현재 쌍 가운데 첫 번째 쌍만 설계·검증한다.

## 1. 이번 설계가 바꾸는 체감

지금까지의 메멘토 미리보기는 현재 모험 뒤에 역행 기록을 붙였다. 이번 수직
슬라이스는 시작부터 다르다.

1. 플레이어는 선택 화면을 거치면 **무조건 과거부터** 플레이한다.
2. 회색빛 공동 창작관에서 전시를 살리기 위해 AI를 어떻게 쓸지 직접 고른다.
3. 무대를 연 순간, 같은 카메라와 같은 좌표에서 색이 돌아오며 현재로 바뀐다.
4. 과거의 선택은 현재의 소품, 대사, 수리 절차로 나타난다.
5. 현재의 문제를 수습한 뒤, 장소형 마음 조각 `겹친 무대`를 설득하고 세 작품의
   이름을 제자리로 돌려놓는다.

핵심 체험 문장은 다음과 같다.

> 과거에는 버튼 하나가 시간을 아껴 주었다. 현재에는 그 버튼이 생략한 확인을
> 내가 다시 이어야 한다.

AI를 쓴 행위 자체를 벌하지 않는다. **누가 만들었는지, 어떤 조건으로 쓸 수
있는지, 무엇을 바꿨는지, AI의 도움을 밝혔는지**가 결과를 바꾼다.

## 2. 기존 게임과의 관계

이 문서는 원본 경로를 덮어쓰지 않는다.

| 경로 | 계약 |
|---|---|
| `원래 모험 시작` | 기존 프롤로그, 다섯 거리, 반디=영이, 고요, 네 엔딩을 그대로 유지한다. |
| `메멘토 시간선 체험` | 기존의 빠른 기록 체험을 장기적으로 `과거 플레이 → 현재 결과` 캠페인으로 확장한다. 첫 구현은 이 문서의 공동 창작관 한 쌍만 제공한다. |

### 2.1 새 캠페인 진입과 기존 V10 슬롯

구현 목표 세이브 버전은 V11이다. V10 메멘토 슬롯을 새 캠페인으로 자동 이동해
진행 위치를 바꾸지 않는다.

| 슬롯 상태 | V11의 `experienceKind` | 진입 규칙 |
|---|---|---|
| 새 빈 슬롯에서 `메멘토 시간선 체험` 선택 | `consequence-pairs` | 이름 입력 뒤 `공동 창작관`, `phase: past`, `checkpoint: past_start`로 시작. `reset_after` 기록은 열지 않음 |
| 기존 V10 `storyRoute: memento` 슬롯 | `legacy-records` | 기존 실험실·다섯 손상 기록·관리자 단말·코어 복원을 현재 위치에서 그대로 이어감 |
| 기존 V10 `storyRoute: original` 슬롯 | `original` | 원래 모험을 현재 위치에서 그대로 이어감 |
| 이미 V11 값이 있는 슬롯 | 저장된 값 유지 | 경로 선택이나 마이그레이션으로 다른 종류로 덮어쓰지 않음 |

한 슬롯에는 한 경험만 저장한다. `experienceKind`는 슬롯을 만든 뒤 바뀌지 않는다.
`map`, `x/y`, `dir`, `flags`를 여러 캠페인이 공유하거나 서로의 스냅샷으로
복사하지 않는다.

경로를 고른 뒤 세 슬롯 화면은 모든 슬롯을 보여 주되 다음만 진입할 수 있다.

- 선택한 경로와 같은 `experienceKind`의 슬롯
- 아직 비어 있어 선택한 경로로 새로 만들 수 있는 슬롯

다른 종류의 사용 중 슬롯은 `원래 모험 진행 중`, `기존 기록 진행 중`,
`과거·현재 캠페인 진행 중`처럼 표시한다. 확인 버튼을 눌러도 변환하지 않고
`이 슬롯의 진행은 그대로 남아 있어요. 빈 슬롯을 골라 주세요.`라고 안내한다.
빈 슬롯이 없다면 기존 슬롯 삭제 확인 화면으로 갈 수 있지만, 자동 삭제·복사·
초기화는 하지 않는다.

V11 마이그레이션은 V10의 `damagedRecords`, `recordEvidence`, 관리자 단말,
시간순 카드, 기존 챕터 플래그를 수정하지 않는다. `legacy-records`에서는 기존
메멘토 HUD와 기록 흐름을, `consequence-pairs`에서는 공동 창작관과 새 D-1 →
D-10 쌍 시간선을 보여 준다. 두 시간선의 기록·HUD·파이널 상태를 한 화면이나
한 파생 함수에 섞지 않는다.

V10→V11은 `storyRoute: memento`면 `experienceKind: legacy-records`, 그 외에는
`experienceKind: original`을 넣는다. V11 이후 새 빈 슬롯은 원래 경로를 골랐으면
`original`, 메멘토 경로를 골랐으면 `consequence-pairs`를 넣는다. 기존 메멘토
슬롯을 새 캠페인으로 변환하는 기능은 첫 수직 슬라이스 범위 밖이다.

첫 수직 슬라이스가 플레이테스트를 통과하기 전에는 기존 다섯 장의 데이터와
진행을 교체하지 않는다. 새 캠페인의 전체 방향은 다음과 같다.

| 플레이 순서 | 역행 과거 | 현재의 파장 | 중심 주제 | 파장의 범위 |
|---:|---|---|---|---|
| 1 | D-1 공동 창작관 | 겹친 전시 | 저작권·출처 | 세 명의 창작자 |
| 2 | D-3 합성 방송실 | 친구의 목소리와 얼굴이 뒤섞인 기록 | AI 합성·동의 | 친구 사이의 신뢰 |
| 3 | D-5 추천 골목 | 한쪽 이야기만 남은 구역 | 추천·확증 편향 | 한 구역 |
| 4 | D-7 대문짝 신문사 | 도시 전체에 번진 한쪽짜리 속보 | 허위정보·출처 확인 | 도시, 현재 주인공의 정체 공개 |
| 5 | D-10 포근한 관제실 | 사람이 결정하지 않는 편안한 도시 | AI 의존·인간의 판단 | 인간의 선택권 |

플레이어가 만나는 과거는 D-1 → D-3 → D-5 → D-7 → D-10으로 멀어진다.
현재는 1쌍부터 5쌍까지 앞으로 진행한다. 파이널은 과거를 D-10 → D-1로 직접
정렬해 두 흐름을 결합한다.

## 3. 설계 원칙

### 3.1 선택은 많되 분기는 모듈로 만든다

- 각 창작실에는 `직접 복구`, `AI와 함께 복구`, `AI 즉시 채우기` 성격의 세
  행동이 있다.
- 화면에는 `선함`, `나쁨`, `정답`, `오답`을 표시하지 않는다.
- 과거의 모든 세부 행동은 소수의 사실 태그로 바꾼다.
- 현재는 태그 조합별 전용 스토리를 만들지 않고, 그림·음악·글의 독립 수리
  모듈을 조립한다.
- 신중한 선택에도 기본 문제가 남는다. 지름길을 쓰지 않았다는 이유로 현재
  탐색이나 피날레를 건너뛰지 않는다.

### 3.2 지름길은 쉬워야 하지만 함정이어서는 안 된다

- AI 즉시 채우기는 과거 작업을 실제로 1~2분 줄인다.
- 시간제한이나 몰래 줄어드는 게이지는 없다.
- 선택 상세에서 `확인하지 않은 항목`을 미리 볼 수 있다.
- 현재의 추가 일은 체력 감소나 더 빠른 마음의 파도가 아니라 **확인·표시·대체
  절차**다.
- 일지는 지름길의 이점도 기록한다. 예: `전시 칸을 즉시 채움`.

### 3.3 권리 판단은 네 단계만 다룬다

1. 만든 사람이 누구인지 확인한다.
2. 어떤 조건으로 쓸 수 있는지 확인한다.
3. 변경·전시하려는 범위가 그 조건에 맞는지 확인한다.
4. 출처와 AI의 도움을 기록한다.

출처를 썼다고 모든 이용이 허용되는 것은 아니다. 게임 속 허구의 사용 조건은
이 네 단계를 연습하도록 단순화한다. 실제 CCL의 출처·조건·변경 범위 원칙은
[한국저작권위원회 공유마당 안내](https://gongu.copyright.or.kr/gongu/main/contents.do?menuNo=200093)를
설계 근거로 삼되, 본편을 법률 문제 풀이로 만들지 않는다.

## 4. 공간과 인물

### 4.1 장소: 공동 창작관

작은 창작회가 전시 전날 빌린 오래된 건물이다. 밤사이 동기화 장치가 망가져
그림, 음악, 인쇄물의 원본 일부가 서로 겹쳤다. AI 복원 단말은 빈칸을 빠르게
채울 수 있지만, 빠른 모드는 만든 사람과 이용 조건을 확인하는 절차를 생략한다.

중앙 전시실에서 세 방을 자유로운 순서로 방문한다.

| 구역 | 과거 | 현재 | 통행 계약 |
|---|---|---|---|
| 중앙 전시실 | 빈 액자, 꺼진 스피커, 비어 있는 설명판 | 세 작품이 한 무대에 겹쳐 반복됨 | 시작·전환·피날레가 모두 같은 카메라에서 일어남 |
| 그림 작업실 | 손상된 밑그림과 다솔 | 서로 다른 그림이 같은 이름표를 요구함 | 과거/현재 충돌 타일 동일 |
| 녹음실 | 고장 난 수신기와 윤슬의 예약 메시지 | 뒤늦게 도착한 고정 답장과 겹친 음원 | 소리 없이도 파형·선 패턴으로 구분 가능 |
| 인쇄실 | 해온의 사용 조건 카드와 찢어진 문장 | 방향을 잘못 가리키는 설명문 | 자유 입력 없이 문장 조각을 배열함 |
| 작은 무대 | 전시 조립과 공개 단말 | 장소형 마음 조각 `겹친 무대` | 마지막 설득 배틀 |
| 기록 보관함 | 닫혀 있음 | 첫 현재 단서를 보면 열림 | 과거 원장이 비었을 때만 추가 복원 단계가 생김 |

과거와 현재는 `mapId`, 카메라 중심, 플레이어 좌표, 벽·문·통행 가능한 타일을
공유한다. 팔레트, 소품 상태, NPC, 조사 문구만 바꾼다. 시간선이 바뀌며 새
충돌물 속에 끼는 경우가 없어야 한다.

### 4.2 세모난 창작회

세 인물과 모든 작품은 가상 데이터다.

| 인물 | 담당 | 과거의 접점 | 현재에 남기는 도움 |
|---|---|---|---|
| 다솔 | 그림 | 현장에 있다. 복원 범위와 전시 허락을 직접 말한다. | 원본의 삐뚤한 별표를 알아보는 표식 |
| 윤슬 | 음악 | 로컬 단말의 예약 메시지로만 등장한다. 안테나를 고치면 고정 답장을 받는다. | 허용된 음원의 파형과 사용 조건 |
| 해온 | 글·인쇄 | 등록된 연락 수단이 만료되어 변경 허락을 확인할 수 없다. | 인쇄실에 남긴 이용 조건과 원문 일부 |

실제 통신, 실시간 답장, 이메일, 메신저, 업로드는 없다. 윤슬의 답장은 과거에
`답장 요청`을 남겼다면 현재 첫 체크포인트에서 결정적으로 도착한다. 해온에게
연락할 수 없다는 사실은 위기나 실종이 아니라 **허락 범위를 더 확인할 수 없는
상태**다.

### 4.3 플레이어와 반디의 복선

- 과거 플레이어는 `전시 담당자`로 표시하며 회색 외투와 네모난 가방을 쓴다.
- 현재 플레이어는 기존 수호자 실루엣과 색을 쓴다.
- 두 인물은 같은 위치에서 왼손으로 단말을 만지고, 가방의 작은 둥근 잠금쇠가
  같다. 4번째 현재 장의 정체 공개 전에는 동일 인물이라고 확정하지 않는다.
- 과거에는 이름 없는 `작업 보조등`이 한두 줄만 말한다. 말끝과 빛의 리듬은
  반디와 같지만, 반디는 현재 기억이 손상되어 그 장면을 안다고 행동하지 않는다.
- 고요 표식은 공개 단말의 `기록 보존 권장` 경고로만 나온다. 고요가 공개를
  막는 악역처럼 보이지 않게 실제 이유도 함께 표시한다.

## 5. 38분 기준 플레이 흐름

측정 범위는 첫 이동 입력부터 결과 카드가 닫힐 때까지다. 방 순서와 선택에 따라
30~40분 안에서 움직인다.

| 시간 | 구간 | 플레이 행동 | 완료 표식 |
|---:|---|---|---|
| 0:00~2:00 | 회색 과거 도입 | 빈 전시를 조사하고 복원 단말을 켠다. | `past_started` |
| 2:00~4:00 | 위기와 선택 문법 | 다솔, 윤슬 메시지, 해온 조건 카드를 본다. | 세 방 개방 |
| 4:00~14:00 | 과거 세 작업실 | 자유 순서로 세 창작물을 복구한다. | 그림·음악·글 선택 3개 |
| 14:00~17:00 | 과거 무대 조립 | 세 결과를 놓고 출처 원장을 어떻게 남길지 고른다. | `past_done` |
| 17:00~18:00 | 같은 카메라 전환 | 회색 과거가 멈추고 현재의 색과 수호자로 바뀐다. | 원자적 전환 저장 |
| 18:00~23:00 | 현재 기본 조사 | 세 방의 기본 손상과 기록 보관함을 확인한다. | 기본 수리 3개 노출 |
| 23:00~29:00 | 현재 수리 | 기본 수리와 과거 태그에서 파생된 추가 수리를 끝낸다. | `repairs_ready` |
| 29:00~36:00 | 겹친 무대 | 3단계 마음 조각 배틀로 작품과 이름을 분리한다. | `stage_restored` |
| 36:00~38:00 | 결과와 다음 문 | 따라와 짧게 대화하고 사실 일지를 확인한다. | `pair_complete` |

모든 즉시 채우기를 고르면 과거는 약 4분 짧아지고 현재 수리가 약 4~6분
길어진다. 모든 확인 절차를 밟으면 과거는 길고 현재는 짧다. 어느 쪽도 전체
콘텐츠나 피날레를 잃지 않는다.

## 6. 과거: 세 작업실의 행동

선택 메뉴는 기존 대화 상자를 사용한다. 각 선택에는 예상 작업량과 지금 확인한
범위만 표시한다. 숨겨진 도덕 점수는 없다.

### 6.1 그림 작업실

기본 문제는 스캔 순서가 뒤섞여 원본의 선이 세 군데 비어 있는 것이다.

| 화면 선택 | 약 1회 시간 | 실제 행동 | 결과 ID | 사실 태그 |
|---|---:|---|---|---|
| `밑그림 조각을 직접 맞춘다` | 2분 30초 | 세 레이어의 삐뚤한 별표를 이어 원본을 복원 | `visual_manual` | `creator_known`, `scope_confirmed`, `authorship_clear` |
| `다솔과 AI 복원본을 고른다` | 1분 30초 | AI 후보 셋 중 다솔이 승인한 선을 고르고 AI 도움표시를 붙임 | `visual_assisted` | 위 세 태그 + `ai_disclosed` |
| `공개된 그림까지 섞어 즉시 채운다` | 15초 | 단말이 비슷한 조각으로 빈칸을 채움 | `visual_instant` | `slot_filled_fast`, `source_mixed`, `scope_unchecked`, `ai_hidden` |

다솔은 어느 선택에서도 플레이어를 비난하지 않는다.

> 다솔: “완벽한 선보다 내가 그린 선을 찾고 싶어. 삐뚤한 건 증거가 되기도
> 하거든.”

### 6.2 녹음실

기본 문제는 전시 곡의 마지막 여덟 박자가 손상된 것이다. 모든 화면 단서는
소리와 함께 파형 모양·번호·진동 표식을 제공한다.

| 화면 선택 | 약 1회 시간 | 실제 행동 | 결과 ID | 사실 태그 |
|---|---:|---|---|---|
| `안테나를 고쳐 윤슬의 답장을 받는다` | 2분 30초 | 케이블을 잇고 고정 답장에서 허용된 마지막 박자를 받음 | `audio_reply` | `creator_known`, `scope_confirmed`, `authorship_clear` |
| `조건이 적힌 임시 음원을 쓴다` | 1분 | `전시 가능·편곡 가능·이름 표시` 세 조건을 맞춰 임시 음원 배치 | `audio_licensed` | `creator_known`, `scope_confirmed`, `credit_recorded` |
| `공개 클립과 비슷한 목소리로 즉시 채운다` | 15초 | 허구의 내장 조각으로 비슷한 소리를 만듦. 생성 절차는 묘사하지 않음 | `audio_instant` | `slot_filled_fast`, `source_mixed`, `consent_missing`, `ai_hidden` |

### 6.3 인쇄실

기본 문제는 안내문의 가운데 문장이 찢어진 것이다. 해온의 카드에는 `짧은 인용
가능 · 이름과 제목 표시 · 문장 변경은 확인 필요`라고 적혀 있다.

| 화면 선택 | 약 1회 시간 | 실제 행동 | 결과 ID | 사실 태그 |
|---|---:|---|---|---|
| `새 연결문을 만든다` | 2분 | 미리 준비된 낱말 조각을 배열해 창작회 명의의 짧은 문장을 만듦 | `text_new` | `new_material`, `authorship_clear`, `scope_confirmed` |
| `조건 안에서 짧게 인용한다` | 1분 | 허용된 한 줄과 해온의 이름·제목을 함께 배치 | `text_excerpt` | `creator_known`, `scope_confirmed`, `credit_recorded` |
| `AI가 빈 글 전체를 추정하게 한다` | 15초 | 남은 문장 전체를 자동으로 채움 | `text_instant` | `slot_filled_fast`, `scope_unchecked`, `consent_missing`, `ai_hidden` |

해온의 연락이 닿지 않아도 `새 연결문`과 `조건 안의 인용`이 항상 가능하다.
연락 부재를 허락으로 간주해야만 진행되는 경우는 없다.

### 6.4 과거 무대 조립과 원장

세 작품을 올리면 공개 단말이 결과를 사실로 요약한다.

```text
[전시 준비 기록]
그림: 다솔 확인 / AI 도움 표시
음악: 사용 조건 확인 / 윤슬 답장 대기
글: 해온의 짧은 인용 / 제목 표시
```

플레이어는 다음 중 하나를 고른다.

| 선택 | 과거의 이점 | 저장 상태 | 현재의 영향 |
|---|---|---|---|
| `원장을 확인하고 연다` | 60~90초의 이름표 연결 작업 뒤 공개 | `complete` | 추가 기록 수리 없음 |
| `확인 못 한 칸을 남기고 연다` | 바로 공개, 빈칸은 화면에 남음 | `partial` | 현재에서 빈칸 하나를 확인 |
| `표시 없이 지금 연다` | 바로 공개, 가장 짧음 | `missing` | 현재 기록 보관함에서 원장 조각 복원 |

고요 표식은 `원본과 복원본의 이름이 겹침 · 기록 보존 권장`이라고 말한다.
플레이어가 공개를 선택해도 강제로 막지 않는다. 이 경고를 본 사실은 어느
선택에서도 일지에 남는다.

## 7. 과거에서 현재로 바뀌는 순간

전환은 작은 무대를 정면으로 보는 동일 카메라에서 한 번만 일어난다.

1. 과거 플레이어가 공개 단말에 손을 얹는다.
2. 소리가 한 박자 멈추고 `현재보다 1일 전` 표지가 `현재`로 바뀐다.
3. 회색 재질에 현재의 청록·호박·라벤더 색이 450ms 동안 돌아온다.
4. 플레이어 실루엣은 같은 좌표에서 현재 수호자로 바뀐다.
5. 빈 무대가 아니라 세 작품이 한 자리를 차지하려는 현재 이상현상이 보인다.

전면 흰색 플래시, 글리치, 흔들림은 사용하지 않는다. `reduceFx`에서는 2~4단계를
즉시 적용하고 `[과거 종료]`, `[현재 시작]` 문장을 순서대로 읽는다. 전환 저장은
`past_done`, 현재 시간선, 좌표를 한 번에 기록한다. 새로고침하면 현재 첫
대사부터 재개하며 과거 공개를 반복하지 않는다.

## 8. 현재: 기본 문제와 선택의 파장

### 8.1 누구에게나 생기는 기본 문제

동기화 실패 자체가 있었으므로 신중하게 준비한 플레이어도 세 방을 다시 돈다.

| 기본 수리 | 장소 | 조작 | 얻는 사실 |
|---|---|---|---|
| `visual_panel` | 그림 작업실 | 세 레이어를 삐뚤한 별표 기준으로 맞춘다. | 어떤 선이 다솔의 원본인지 |
| `music_cue` | 녹음실 | 파형 모양과 번호를 맞춰 마지막 여덟 박자를 분리한다. | 어떤 박자가 전시 허용본인지 |
| `text_panel` | 인쇄실 | 원문·새 문장·자동 추정문을 서로 다른 인쇄틀에 놓는다. | 어느 문장이 누구의 것인지 |

신중한 과거 태그가 있으면 다솔의 별표, 윤슬의 파형, 해온의 조건 카드가 더
선명한 도움으로 남는다. 그렇더라도 수리는 직접 수행한다.

### 8.2 지름길에서 파생되는 추가 수리

추가 수리는 저장 배열에 직접 더하지 않고 과거 결과에서 순수하게 계산한다.
각 창작물은 최대 하나의 추가 수리만 만든다.

| 조건 | 추가 수리 ID | 현재 행동 | 해결 결과 |
|---|---|---|---|
| `visual_instant` | `visual_rights_review` | 섞인 공개 조각을 분리하고 다솔이 승인한 복원본으로 대체 | `illustrator_scope_confirmed` 또는 `illustrator_declined_and_replaced` |
| `audio_instant` | `music_license_review` | 현재 도착한 윤슬의 고정 답장과 파형을 대조해 허용본으로 교체 | `musician_scope_confirmed` 또는 `musician_declined_and_replaced` |
| `text_instant` | `text_replacement` | 변경 허락이 없는 추정문을 빼고 새 연결문 또는 허용 인용을 배치 | `writer_permission_unverified`, `writer_material_replaced` |
| 원장 `partial` | `ledger_blank` | 비어 있는 이름표 한 칸을 현재 사실로 채움 | `creator_credit_recorded` |
| 원장 `missing` | `ledger_fragments` | 기록 보관함의 세 조각을 작품과 연결 | `creator_credit_recorded`, `ai_assistance_recorded` |

모든 추가 수리를 가진 극단 조합도 세 창작실 + 기록 보관함 안에서 끝난다.
별도 방, 새 인물, 새 퍼즐 규칙을 추가하지 않는다.

### 8.3 진행 불변식

```text
필수 추가 수리 = 과거 결과에서 파생한 수리의 중복 없는 집합

피날레 준비 = 기본 수리 3개 완료
             + 필수 추가 수리 모두 완료
```

수리 중 무엇을 먼저 해도 중앙 전시실로 돌아올 수 있다. 윤슬의 답장이나 해온의
상태는 실제 시계, 네트워크, 확률에 의존하지 않는다. 모든 분기는 오프라인에서
결정적으로 끝난다.

## 9. 겹친 무대: 7분 마음 조각 배틀

### 9.1 정체와 완료 의미

`겹친 무대`는 사람이 아니다. 세 창작자의 목소리와 `따라`의 “남의 것을
따라야만 빈칸을 채울 수 있다”는 마음이 한 장소에 겹쳐 굳은 **장소형 마음
조각**이다. 무대를 부수지 않고 작품·이름·도움을 분리하면 마음이 열린다.

표면 제목은 `[장소형 마음 조각] 겹친 무대`다. 구현은 기존 설득 배틀의 입력,
마음 게이지, 연습 파도, TTS를 재사용하되 다음 값에는 쓰지 않는다.

- 기존 `mercy` 점수
- S/A/B식 평가
- `mercy/neutral/harsh` 선택
- 기존 인물의 `defeated` 또는 수첩 완료 상태

완료는 이 슬라이스의 `stage_restored` 사실만 남긴다.

### 9.2 내 차례

기존 네 메뉴를 유지한다.

| 메뉴 | 이 피날레에서 하는 일 |
|---|---|
| `가만히 듣기` | 그림·음악·글 중 아직 구분하지 못한 한 목소리를 듣고 다음 파도의 비색상 단서를 얻는다. |
| `증거 보여주기` | 현재 수리에서 얻은 `원본의 이름`, `허락의 범위`, `AI 도움 표시` 중 현재 겹침에 맞는 사실을 놓는다. |
| `말 걸기` | 탐색에서 해금한 짧은 문장으로 “비슷해도 같은 이름은 아니다”, “빌린 조건도 함께 남는다”, “AI가 도운 자리를 숨기지 않는다”를 전한다. |
| `마음 안아 주기` | 마음이 열린 뒤 세 이름표를 작품 앞에 돌려놓고 배틀을 끝낸다. |

증거 선택은 법률 정답 퀴즈가 아니다. 같은 방에서 직접 복원한 소품과 무대의
겹침을 대조하는 행동이다. 맞지 않는 증거를 놓아도 게이지를 빼지 않고, 무대가
`지금 겹친 것은 소리가 아니라 선이야`처럼 다음 관찰을 돌려준다.

### 9.3 상대 차례의 세 단계

| 단계 | 화면 패턴 | 플레이 행동 | 성공 표식 |
|---|---|---|---|
| 1. 겹친 선 | 하트가 지나간 길을 2초 뒤 회색 선이 따라옴 | 같은 길을 반복하지 않고 새 경로를 그린다. 첫 파도는 피해 없는 연습이다. | 다솔의 삐뚤한 별표가 고정됨 |
| 2. 겹친 음 | 서로 다른 선 패턴의 안전 구역이 박자마다 겹침 | 이름·번호가 붙은 파형 구역으로 마음 조각을 돌려보낸다. | 윤슬의 여덟 박자가 분리됨 |
| 3. 겹친 말 | 자동 추정문 화살표가 여러 방향을 가리킴 | 해온의 조건 카드와 같은 모양·밑줄을 가진 방향으로 이동한다. | 원문·새 문장·AI 도움표시가 나뉨 |

소리만 듣거나 색만 구분해야 통과하는 패턴은 없다. 과거 선택에 따라 탄속,
밀도, 피해량을 올리지 않는다. 현재 수리를 마친 뒤 들어오므로 모든 플레이어는
같은 공정한 피날레를 경험한다.

### 9.4 회복과 도움

- 마음이 다 닳으면 피날레의 현재 단계 시작으로 돌아간다. 약 60~90초만
  재시도한다.
- 방 수리, 창작 기록, 답장, 원장, 해금한 말과 증거는 모두 보존한다.
- 시도 횟수는 결과나 엔딩 신호에 저장하지 않는다.
- 두 번 잠시 물러난 뒤 반디가 현재 단계의 카운터 행동을 한 줄로 말한다.
- 세 번 잠시 물러난 뒤 `느린 파도`를 선택할 수 있다. 이동하는 선과 안전 구역의
  속도를 25% 낮추되, 내용과 완료 결과는 같다.
- `느린 파도`, `효과 줄이기`, `큰 글씨`, `저사양` 사용 여부는 사실 일지나
  교사용 평가에 남기지 않는다.

### 9.5 마무리 장면

세 작품이 서로 밀어내지 않고 나란히 선다. 작품 아래에는 만든 사람, 사용한
조건, AI가 도운 부분이 짧게 나타난다. 종이 더미 안에서 `따라`가 빈 종이를
들고 나온다.

> 따라: “빈칸을 남겨도 되는 거였네. 남의 이름으로 급히 채우지 않아도.”<br>
> 반디: “빈칸은 실패가 아니야. 다음 사람이 사실을 놓을 자리일 수도 있어.”

`따라`와 함께한 기존 의미는 폐기하지 않되, 이 슬라이스는 기존 따라 배틀의
거친 선택, 랭크, 자비 값을 재사용하지 않는다.

### 9.6 기존 설득 엔진과의 완료 어댑터

피날레 프로필은 다음 식별자를 고정한다.

```js
{
  persuadeId: 'overlapped_stage',
  subjectKind: 'place',
  completionMode: 'stage',
}
```

`subjectKind: place`는 기존 인물 조회를 요구하지 않는다. 데이터는 장소형 마음
조각의 이름, 관찰, 말, 증거, 세 파도만 제공한다. 게이지가 찬 뒤 `마음 안아
주기`를 선택하면 일반 `persuadeTriumph()`의 자비 선택으로 가지 않고
`completeStagePersuasion()`으로 분기한다.

`completeStagePersuasion()`의 효과는 정확히 다음과 같다.

1. 세 이름표 배치 장면을 연다.
2. `copyrightSlice.stageRestored = true`와 `checkpoint: complete`를 저장한다.
3. 기존 `mercy`, `mercyChoice`, `defeated`, 친구 수첩, 배틀 랭크를 바꾸지 않는다.
4. 결과 대화 뒤 공동 창작관 출구와 마음의 문 허브를 연다.

피날레 저장 필드는 `segment: 0|1|2|3`, `assistLevel: 0|1|2`,
`slowWaveEnabled: boolean`이다. 한 단계를 끝냈을 때만 다음 `segment`를 저장한다.
잠시 물러나면 저장된 단계의 첫 파도에서 재개한다. `assistLevel`은 도움의
일관된 재개를 위해 슬롯에 남기지만 일지, 엔딩 신호, 교사용 화면, 분석 값으로
투영하지 않는다.

## 10. 창작 기록: 사실만 남기는 일지

기존 모험 일지 안에 `창작 기록` 페이지를 재사용한다. 별도의 점수·수집 메뉴를
만들지 않는다. 문장은 화이트리스트 상태에서만 만든다.

### 10.1 표시 필드

| 필드 | 허용 값 |
|---|---|
| 만든 사람 | `확인됨`, `확인하지 못함`, `새로 만듦` |
| 이용 조건 | `범위 확인`, `확인하지 못함`, `해당 없음` |
| AI 도움 | `표시함`, `아직 표시하지 않음`, `사용하지 않음` |
| 전시 결과 | `칸을 채움`, `대체함`, `분리함`, `이름을 기록함` |

`좋음`, `나쁨`, `현명함`, `부주의`, 등급, 점수, 정답률은 표시하지 않는다.

### 10.2 예시

```text
[과거 작업 기록]
음악: 공개 조각을 섞어 전시 칸을 즉시 채움.
만든 사람: 확인하지 못함.
AI 도움: 아직 표시하지 않음.

[현재 확인 기록]
윤슬의 답장으로 허용 범위를 확인함.
비슷하게 만든 음원을 빼고 허용본으로 대체함.
AI가 도운 위치를 이름표에 기록함.
```

일지는 과거의 정답을 몰래 바꾸지 않는다. 과거에 보였던 사실과 현재 새로
확인한 사실을 시간 표시와 함께 나란히 둔다.

## 11. 상태와 저장 계약

상태는 기존 미리보기 저장 공간 안에만 둔다. 운영 저장 키를 읽거나 옮기지
않는다. 구현 시 `src/memento.js`의 순수 투영 패턴을 확장하고 화면 커서나 함수는
저장하지 않는다.

슬롯 루트의 `experienceKind`가 활성 경험을 결정한다. `storyRoute`는 V10 코드와
백업 호환을 위해 `original | memento`로 남기되, 두 메멘토 세대를 구분할 때는
사용하지 않는다. `legacy-records`와 `consequence-pairs`는 모두
`storyRoute: memento`다.

```js
copyrightSlice = {
  phase: 'past' | 'switch' | 'present' | 'finale' | 'result',
  checkpoint: 'past_start' | 'past_rooms' | 'past_done' |
    'present_start' | 'repairs_done' | 'finale_start' | 'complete',
  pastChoices: {
    visual: null, // visual_manual | visual_assisted | visual_instant
    audio: null,  // audio_reply | audio_licensed | audio_instant
    text: null,   // text_new | text_excerpt | text_instant
    ledger: null, // complete | partial | missing
  },
  baseRepairs: {
    visual_panel: false,
    music_cue: false,
    text_panel: false,
  },
  addedRepairs: {},
  finale: {
    segment: 0,
    assistLevel: 0,
    slowWaveEnabled: false,
  },
  stageRestored: false,
  complete: false,
};
```

`addedRepairs`는 로드할 때 `pastChoices`에서 다시 계산한다. 미래 버전의 알 수
없는 필드는 삭제하지 않는다.

### 11.1 체크포인트

| 시점 | 저장 내용 | 재개 화면 |
|---|---|---|
| 과거 진입 | 과거 시작, 중앙 전시실 좌표 | 위기 안내 뒤 자유 탐색 |
| 각 방 완료 | 해당 결과 ID와 사실 태그 | 그 방 출구 앞 |
| 과거 무대 공개 | 선택 3개, 원장 상태, `past_done` | 같은 카메라 전환 직전 |
| 현재 전환 완료 | 현재 시간선과 현재 좌표를 원자 저장 | 현재 첫 겹침 대사 |
| 각 수리 완료 | 기본 수리와 파생 수리 상태 | 해당 방 출구 앞 |
| 수리 전체 완료 | `phase: present`, `checkpoint: repairs_done`, 모든 수리·해금 사실 | 겹친 무대 문 앞 |
| 피날레 시작 | `phase: finale`, `checkpoint: finale_start`, `segment: 0` | 첫 무피해 연습 파도 |
| 피날레 단계 완료 | 현재 단계 번호만 | 다음 단계 첫 파도 |
| 결과 완료 | `stage_restored`, `pair_complete` | 마음의 문 허브 |

`repairs_done` 재개는 피날레 문 앞이며 파도를 시작하지 않는다. 문을 여는 입력이
`phase: finale`, `checkpoint: finale_start`, `segment: 0`을 한 원자 저장으로 바꾼
뒤에만 첫 파도를 시작한다.

건너뛰어도 되는 것은 시간선 전환 연출과 결과 대사의 이미 확인한 페이지뿐이다.
과거 선택, 현재 수리, 피날레는 건너뛰기로 완료 처리하지 않는다. 일시정지와
오프라인 재개는 모든 체크포인트에서 동작해야 한다.

## 12. 화면·모바일·접근성

### 12.1 시간선 구분

| 요소 | 과거 | 현재 |
|---|---|---|
| 팔레트 | `reverse-*` 네 단계 회색 | 기존 순행 색 토큰 |
| 표지 | `[과거 ←] 현재보다 1일 전` | `[현재 →] 공동 창작관` |
| 테두리 | 끊긴 선과 모서리 손상 표식 | 연속 흰색·청록 선 |
| 소리 | 짧고 낮은 단음 | 같은 음형에 따뜻한 화음 추가 |

색을 끄거나 소리를 끄더라도 표지와 선 모양만으로 구분할 수 있어야 한다.

### 12.2 입력

- 키보드, 게임패드, 터치는 같은 행동을 수행한다.
- 대화/행동 선택은 기존 선택 UI와 Z/Enter를 쓴다.
- X/Escape는 뒤로 가기 또는 이미 본 대사 닫기만 수행한다.
- 터치 표적은 최소 44×44px다.
- 자유 텍스트, 파일 선택, 카메라, 마이크, 클립보드를 사용하지 않는다.

### 12.3 뷰포트와 효과

- 1280×800, 390×844, 844×390에서 안전 여백과 조작 패널을 확인한다.
- 큰 글씨에서 선택 설명은 한 화면에 최대 세 줄이며, 상세 정보는 별도 한 장으로
  넘긴다.
- TTS는 시간선 표지, 방 이름, 선택 결과, 사실 일지를 읽는다. 새 문장을 읽기
  전에 이전 음성을 멈춘다.
- `reduceFx`에서는 전환, 이름표 고정, 레이어 분리 애니메이션을 0ms로 한다.
- `lowGraphics`에서는 장식 레이어만 줄이며 원본/복원본 구분 표식은 지우지 않는다.

## 13. 아동 안전과 교육 경계

- 모든 사진, 그림, 목소리, 글, 이름은 게임에 내장된 가상 데이터다.
- 실제 친구나 유명인의 얼굴·목소리를 넣거나 흉내 내는 절차를 보여 주지 않는다.
- 외부 사이트로 전송, 공개, 공유하는 장면은 극중 단말의 가상 전시로만 표현한다.
- 플레이어가 침해 방법을 상세히 따라 할 수 있는 프롬프트·도구 이름·설정 절차를
  제공하지 않는다.
- 창작자는 화내거나 창피를 주는 심판이 아니다. 허용 범위와 자신의 마음을 짧게
  말하고, 거절하면 안전한 대체본을 함께 찾는다.
- `연락이 안 됨 = 허락`으로 가르치지 않는다.
- AI 도움표시는 부끄러움이 아니라 작업 사실로 다룬다.
- 본편에 OX, 점수형 법률 문제, 긴 설명식 교훈을 넣지 않는다.
- 새 개인정보, 학생 데이터, 원격 분석, 교사용 CSV 필드를 추가하지 않는다.

### 14.2 조합 폭 제한

- 과거 결과 3×3×3×3은 저장할 수 있지만 손으로 81개 분기를 쓰지 않는다.
- 세 창작실의 추가 수리는 각자 `즉시 채우기인가`만 보고 독립 파생한다.
- 원장 추가 수리는 `complete/partial/missing`만 본다.
- 피날레는 과거 선택과 무관하게 한 버전이다.
- 대사는 `기본 문장 + 해당 사실 한 줄`로 조립하고 한 화면 3줄을 넘지 않는다.

브라우저 자동화는 다음 실제 조작을 고정한다.

1. **1280×800 · 새 메멘토 슬롯:** `메멘토 시간선 체험 → 빈 슬롯 → 이름 입력`
   뒤 공동 창작관을 직접 이동한다. `[과거 ←]`, 회색 선 패턴, 세 방 선택을

2. **390×844 · 효과 줄이기:** 모든 과거 선택을 즉시 채우기로 고르고 원장 없이
   연다. 같은 좌표에서 전환 시간이 0ms이며 `[과거 종료] → [현재 시작]` ARIA/TTS
   순서와 터치 버튼 44px를 확인한다.
3. **844×390 · 혼합 선택:** `visual_assisted`, `audio_instant`, `text_excerpt`,
   `partial` fixture로 현재를 연다. 기본 수리 셋과 정확히
   `music_license_review`, `ledger_blank`만 보이고 조작 안내가 잘리지 않는지
   확인한다.
4. **피날레·접근성:** 키보드, 터치, 게임패드로 세 단계를 각각 한 번 통과하고,
   두 번 잠시 물러나 힌트, 세 번 뒤 느린 파도를 켠다. 완료 뒤 기존 자비·랭크·
   수첩이 바뀌지 않았음을 확인한다.
5. **오프라인 재개:** 과거 방, 전환 직전, 현재 추가 수리, 피날레 2단계에서 각각
   네트워크를 끊고 새로고침한다. 고정 윤슬 답장과 저장된 단계가 외부 요청 없이
   복원되는지 확인한다.

스크린샷과 로그는 구현 시 `.orchestration/evidence/copyright-slice/` 아래에
뷰포트·상태 이름으로 남긴다. 문서만 작성하는 현재 커밋에서는 실행 코드를
가정한 가짜 RED/GREEN 로그를 만들지 않는다.

## 15. 제작 범위

### Must: 첫 플레이테스트에 반드시 포함

- 한 개의 공유 지오메트리와 과거/현재 팔레트
- 세 작업실의 각 3개 행동
- 결과 ID → 기본/추가 수리의 순수 파생
- 세 기본 수리, 최대 세 창작물 추가 수리, 원장 추가 수리 하나
- 동일 카메라 시간선 전환과 원자적 저장
- 3단계 `겹친 무대`, soft retry, 느린 파도
- 사실 전용 창작 기록
- 키보드·터치·게임패드, 큰 글씨, 효과 줄이기, 저사양, TTS
- 오프라인 시작·재개

### Should: 첫 외부 데모 전 포함

- 방마다 다른 재질과 4~6개 생활 소품
- 다솔의 두 표정, 윤슬 답장 파형, 해온의 활자 애니메이션
- 과거/현재 같은 좌표를 보여 주는 짧은 비교 연출
- 교사용 안내서의 사후 토론 질문. 학생 화면에는 노출하지 않음

### Deferred: 수직 슬라이스 검증 뒤

- 나머지 네 과거/현재 쌍
- 4번째 현재 장의 주인공 정체 공개
- D-10 → D-1 최종 시간순 복원
- 네 엔딩과 전체 행동 사실의 결합
- 첫 엔딩 뒤 `시간선 실험실`
- 신규 그래픽·음악의 대량 제작과 전체 캠페인 밸런싱

## 16. 구현 수락 조건

### 16.1 정상 경로

1. 새 슬롯에서 메멘토 체험을 고르면 90초 안에 회색 과거를 직접 조작한다.
2. 세 방의 순서를 자유롭게 골라도 과거 무대를 열 수 있다.
3. 세 행동 모두 진행 가능하며 즉시 채우기가 실제로 가장 짧다.
4. 같은 카메라에서 현재로 전환되고 과거 선택이 현재 소품과 일지에 보인다.

### 16.2 조합·실패 경로

2. 모든 직접 복구 조합에도 세 기본 수리와 전체 피날레가 남는다.
3. 모든 즉시 채우기 + 원장 없음 조합에도 추가 수리는 최대 네 모듈이며 진행이
   막히지 않는다.
4. 허락을 확인하지 못하면 `대체` 경로가 항상 있다.
5. 피날레에서 잠시 물러나도 방 수리와 사실 카드는 남는다.
6. 두 번 뒤 힌트, 세 번 뒤 느린 파도가 열리며 결과는 동일하다.

## 17. 첫 플레이테스트 질문

플레이가 끝난 뒤 정답을 묻지 않고 경험을 묻는다.

1. 과거에서 가장 빨리 끝난 행동은 무엇이었나?
2. 현재에서 왜 그 일을 다시 확인해야 했다고 느꼈나?
3. AI를 사용한 것과 AI 사용을 숨긴 것은 같은 일처럼 느껴졌나?
4. 연락이 닿지 않은 해온의 글을 어떻게 처리했나? 다른 방법도 보였나?
5. 겹친 무대에서 작품을 공격한 느낌이었나, 분리하고 돌려준 느낌이었나?
6. 회색과 컬러 외에 과거/현재를 구분하게 해 준 표식은 무엇이었나?
7. 다시 한다면 다른 행동을 시험하고 싶은가? 그 이유는 무엇인가?

관찰자는 플레이어가 고른 선택을 평가하지 않는다. 다음만 기록한다.

- 첫 과거 조작까지 걸린 시간
- 각 방에서 선택 상세를 열어 본 횟수
- 과거/현재 전환을 말로 설명할 수 있는지
- 현재 추가 수리의 이유를 과거 행동과 연결하는지
- 피날레 단계별 재시도와 힌트 사용
- 총 플레이 시간과 중단 지점

이 수직 슬라이스가 성공했다는 기준은 학생이 “AI를 쓰면 안 된다”라고 말하는
것이 아니다. **“빨리 채운 것과, 확인하고 이름을 남긴 것은 다른 일이다”**라고
자기 플레이를 근거로 설명할 수 있는가다.
