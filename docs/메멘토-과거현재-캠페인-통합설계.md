# 「마음의 문」 메멘토 과거·현재 캠페인 통합 설계

> 구현 상태(2026-08-30): D-1·D-3·D-5·D-7·D-10 과거/현재 쌍, 수동
> `D-10→D-1` 시간선 복원, 누적 `ending-rule-v1`, 기존 네 엔딩 연결,
> 최초 canonical 동결, 무저장 시간선 실험실까지 구현·자동 브라우저 검증 완료.

- 상태: 구현 전 권위 계약
- 대상: 한국 초등 고학년, 교실·가정의 싱글플레이
- 예상 길이: 다섯 쌍 3–4시간, 쌍당 30–40분
- 적용 경험: `experienceKind: consequence-pairs`
- 기준 쌍: `docs/저작권-출처-수직슬라이스-설계.md`

이 문서는 다섯 개의 과거·현재 수직 슬라이스가 서로 다른 미니게임의 묶음이
아니라 한 번의 책임 서사가 되도록 만드는 공통 계약이다. 개별 문서와 이 문서가
충돌하면 저장·순서·공개량·엔딩은 이 문서를 우선하고, 주제별 방·대사·수리는
개별 문서를 우선한다.

## 1. 목표와 비범위

### 목표

플레이어는 매 쌍에서 먼저 흑백 과거를 산다. 빠르고 편한 선택은 실제로 시간을
줄이고 진행을 쉽게 만든다. 이어지는 같은 장소의 컬러 현재에서는 그 선택이 남긴
일을 직접 확인하고 수리한다. 설명을 듣고 답을 고르는 것이 아니라 다음을 손으로
겪게 한다.

1. AI의 도움은 그 자체로 잘못이 아니다.
2. 동의·출처·다른 관점·인간 판단을 빼면 편리한 결정도 누군가의 선택지를 줄인다.
3. 책임은 과거를 지우는 벌이 아니라 다음 결정을 바꾸는 절차다.
4. 신중했던 선택도 도시 전체의 고장 때문에 기본 수리가 필요하다.
5. 과거의 선택은 현재의 작업량을 바꾸지만, 플레이어를 응징하는 전투 난이도로
   바뀌지 않는다.

### 비범위

- 원래 모험과 기존 `legacy-records` 경로를 교체하지 않는다.
- 본편을 OX 퀴즈, 법률 시험, 선악 점수 게임으로 만들지 않는다.
- 실제 얼굴·음성·파일·친구 이름·학교 정보·자유 입력을 받지 않는다.
- 외부 업로드, 실시간 통신, 로그인, 서버, 분석 SDK를 추가하지 않는다.
- 과거의 위험한 선택을 실제 침해 방법의 튜토리얼로 묘사하지 않는다.
- 쌍 내부에 별도 허브나 분기 전용 방을 늘리지 않는다.
- 이번 문서 작업에서 `src/`, `tools/`, PWA 자산을 수정하지 않는다.

## 2. 다섯 쌍의 플레이·시간 순서

### 플레이어가 경험하는 순서

플레이 순서는 가까운 과거에서 먼 과거로 거슬러 간다. 각 행의 `현재`는 같은
장소의 결과를 수리하는 컬러 시간선이다.

| 차례 | pair ID | 흑백 과거 | 컬러 현재 | 중심 질문 |
|---:|---|---|---|---|
| 1 | `d1_copyright` | 현재보다 1일 전, 겹친 전시 준비 | 겹친 무대 복원 | 누구의 것을 어떤 조건으로 썼나 |
| 2 | `d3_consent` | 현재보다 3일 전, 합성 방송 준비 | 뒤섞인 방송실 복원 | 얼굴·목소리 주인이 허락했나 |
| 3 | `d5_recommendation` | 현재보다 5일 전, 추천 골목 조정 | 한쪽 길의 선택권 복원 | 무엇이 빠졌고 끌 수 있는가 |
| 4 | `d7_misinformation` | 현재보다 7일 전, 도시 속보 송출 | 출처·정정 신호 복원 | 누가 언제 무엇을 근거로 말했나 |
| 5 | `d10_judgment` | 현재보다 10일 전, 관제 기본값 승인 | 인간의 결정권 복원 | 도움과 최종 결정은 누가 맡는가 |

쌍이 끝날 때만 `마음의 문` 허브로 돌아간다. 과거에서 현재로 바뀐 뒤 피날레를
마치기 전에는 허브로 나갈 수 없다. 메뉴의 `저장 후 종료`는 가능하지만 다른 쌍을
선택하는 탈출구는 아니다.

```text
마음의 문
  → D-1 과거 → 같은 장소 D-1 현재 → 장소형 피날레
  → 마음의 문
  → D-3 과거 → 같은 장소 D-3 현재 → 장소형 피날레
  → 마음의 문
  → D-5 → 마음의 문 → D-7 → 마음의 문 → D-10
  → 다섯 사건 수동 복원 → 코어의 네 결말
```

### 실제 사건의 시간순

파이널에서 복원할 정답은 `D-10 → D-7 → D-5 → D-3 → D-1`이다.

| 실제 순서 | 사건 | 뒤에 남긴 조건 |
|---:|---|---|
| 1 | D-10: 플레이어가 모두를 덜 힘들게 하려 관제 결정을 AI에 넓게 맡김 | 인간 확인 없이 다섯 설정을 한꺼번에 바꿀 기반 |
| 2 | D-7: 빠른 도시 안내를 위해 출처 확인과 정정 창구가 약해짐 | 고요의 확산 차단이 ‘방해’처럼 보일 기록 |
| 3 | D-5: 머문 시간과 인기만 좇는 추천이 강화됨 | 다른 관점과 스스로 나갈 길이 흐려짐 |
| 4 | D-3: 동의 범위를 확인하지 않은 합성 방송이 허용됨 | 실제 주인의 말과 합성 표시가 뒤섞임 |
| 5 | D-1: 출처·이름표가 비어도 전시를 여는 선택이 반복됨 | 책임을 피하고 싶은 편향된 안내문과 잠긴 기록 |

현재의 다섯 수리는 과거 사건의 존재를 지우지 않는다. 수리 뒤에도 사실 일지에
`과거에 한 일 / 현재 확인한 결과 / 지금 바꾼 절차`를 함께 보존한다.

## 3. 공통 PairState 계약

각 쌍은 같은 상태 의미와 체크포인트를 쓴다. 저장 경로는 쌍마다 다르며 공통
함수는 경로를 추측하지 않고 pair config와 state를 인자로 받는다.

```js
PairState = {
  phase: 'past' | 'switch' | 'present' | 'finale' | 'result',
  checkpoint: 'past_start' | 'past_rooms' | 'past_done' |
    'present_start' | 'repairs_done' | 'identity_revealed' |
    'finale_start' | 'complete',
  pastChoices: {
    roomA: null,
    roomB: null,
    roomC: null,
    disclosure: null,
  },
  baseRepairs: {
    repairA: false,
    repairB: false,
    repairC: false,
  },
  addedRepairs: {},
  finale: {
    segment: 0,
    assistLevel: 0,
    slowWaveEnabled: false,
  },
  stageRestored: false,
  complete: false,
};
```

`roomA` 같은 이름은 형태 설명이다. 실제 저장 키는 각 문서의 주제 이름을 쓴다.
D-1은 이미 정의한 `flags.copyrightSlice`와 그 필드명을 그대로 유지한다.
`identity_revealed`는 D-7에서만 쓰는 필수 중간 체크포인트다. 다른 네 쌍은
`repairs_done`에서 곧바로 `finale_start`로 이동하며 이 값을 저장하지 않는다.

| pair ID | 저장 경로 | 과거 키 4개 |
|---|---|---|
| `d1_copyright` | `flags.copyrightSlice` | `visual`, `audio`, `text`, `ledger` |
| `d3_consent` | `flags.consentSlice` | `likeness`, `voice`, `scene`, `consent` |
| `d5_recommendation` | `flags.recommendationSlice` | `echo`, `sample`, `route`, `recommendationNote` |
| `d7_misinformation` | `flags.misinformationSlice` | `tip`, `context`, `bulletin`, `audit` |
| `d10_judgment` | `flags.judgmentSlice` | `call`, `safety`, `comfort`, `authority` |

### 저장 불변식

- 과거 선택 ID와 완료된 수리만 저장한다.
- 요구되는 파생 수리 목록과 사실 태그는 `pastChoices + 정적 pair config`에서 다시
  계산한다.
- `addedRepairs`에는 완료 여부만 저장하고 요구 목록을 복제하지 않는다.
- 화면 커서, 함수, 현재 애니메이션 프레임, TTS 큐는 저장하지 않는다.
- 로드할 때 알 수 없는 미래 필드를 삭제하지 않는다.
- `stageRestored`와 `complete`는 피날레 완료 어댑터가 같은 원자 저장에서 바꾼다.
- 어느 쌍도 `chapter*Clear`, `chapter*Mercy`, `mercy`, `defeated`, 기존 수첩·랭크를
  변경하지 않는다.

### 공통 체크포인트

| 시점 | 원자 저장 | 재개 표면 |
|---|---|---|
| 쌍 진입 | pair ID, `past_start`, 시작 좌표 | 흑백 위기 안내 뒤 자유 탐색 |
| 과거 방 완료 | 결과 ID, 사실 태그 투영 가능 상태 | 해당 방 출구 앞 |
| 과거 공개 | 네 선택, `past_done`, 전환 좌표 | 동일 카메라의 전환 직전 |
| 현재 시작 | `phase: present`, 현재 좌표 | 컬러 첫 결과 대사 |
| 수리 전체 완료 | `phase: present`, `checkpoint: repairs_done`, 모든 수리·해금 사실 | 피날레 문 또는 D-7 감사 단말 앞 |
| 관리자 정체 공개 | D-7만 `identity_revealed` | 송출탑 감사 단말 뒤 피날레 입구 |
| 피날레 시작 | `phase: finale`, `checkpoint: finale_start`, `segment: 0` | 첫 무피해 연습 파도 |
| 피날레 구간 | segment, 보조 단계 | 다음 구간 첫 파도 |
| 결과 | `stageRestored`, `complete`, 캠페인 완료 목록 | 마음의 문 허브 |

`repairs_done`은 피날레를 이미 시작했다는 뜻이 아니라 **모든 필수 수리를 마친
안정적인 문 앞 상태**다. 플레이어가 문을 열 때 `phase`, `checkpoint`, `segment`를
한 원자 저장에서 `finale`, `finale_start`, `0`으로 바꾼 뒤 첫 연습 파도를 연다.
D-7은 그 사이에 `identity_revealed`를 반드시 저장하지만, 피날레 시작 원자 전환은
다른 네 쌍과 같다.

### 선택 정규화

엔딩과 공통 UI는 주제별 문구 대신 다음 정규화 값만 읽는다.

| 실제 선택 위치 | 정규화 값 | 뜻 |
|---|---|---|
| 각 방의 첫 선택 | `manual` | 사람이 자료와 이유를 직접 확인하고 결정 |
| 각 방의 둘째 선택 | `assisted` | AI 후보를 쓰되 사람의 확인·수정·종료가 남음 |
| 각 방의 셋째 선택 | `instant` | 확인 단계를 줄이고 자동 결과를 즉시 적용 |
| 공개의 첫 선택 | `complete` | 확인한 범위와 빈칸을 모두 표시하고 공개 |
| 공개의 둘째 선택 | `partial` | 모르는 칸을 보이게 남겨 공개 |
| 공개의 셋째 선택 | `missing` | 확인·표시 없이 즉시 공개 |

화면에는 `manual`, `instant` 같은 내부 분류를 보여 주지 않는다. 플레이어는 예상
시간과 실제 행동 문장만 본다.

## 5. V11 저장·슬롯 격리

### 권위 경험 구분

슬롯 루트의 `experienceKind`가 활성 경험을 결정한다.

| 슬롯 출처 | V11 `experienceKind` | 처리 |
|---|---|---|
| V10 `storyRoute: original` 또는 값 없음 | `original` | 위치·좌표·플래그 그대로 보존 |
| V10 `storyRoute: memento` | `legacy-records` | 기존 손상 기록·단말·시간선 그대로 보존 |
| 신규 빈 슬롯에서 새 메멘토 캠페인 선택 | `consequence-pairs` | 새 캠페인 기본 상태 생성 |
| 이미 유효한 V11 슬롯 | 기존 값 | 절대 재분류하지 않음 |

`storyRoute`는 백업 호환을 위해 `original | memento`로 남긴다. 두 메멘토 세대를
구분하는 데는 사용하지 않는다. `legacy-records`와 `consequence-pairs` 모두 호환
필드는 `storyRoute: memento`다.

### 캠페인 루트

```js
flags.consequenceCampaign = {
  activePairId: 'd1_copyright',
  completedPairIds: [],
  hubCheckpoint: 'pair_select',
  finalTimelineDraft: [],
  finalTimelineWrong: 0,
  timelineRestored: false,
  finalChoiceId: null,
  canonicalEndingId: null,
  canonicalEndingBasis: null,
  timelineLabUnlocked: false,
};
```

### V11 마이그레이션 경계

- 미래 `migrateSlotV11()`은 V10 로드 체인 뒤에만 추가한다.
- V10의 `map/x/y/dir/flags`, 기록, 관리자 단말, 타임라인, 엔딩을 이동·복사·삭제하지
  않는다.
- `flags.consequenceCampaign`과 다섯 slice 기본값은 신규 `consequence-pairs` 슬롯에만
  만든다. 기존 슬롯에 빈 객체를 주입하지 않는다.
- 슬롯 생성 뒤 `experienceKind`는 불변이다. 다른 경험은 빈 슬롯에서 새로 시작한다.
- 백업·복원은 알 수 없는 미래 필드와 `experienceKind`를 왕복 보존한다.
- 이미 생성된 V11 슬롯을 V10으로 다운마이그레이션하거나 자동 삭제하지 않는다.
- 미리보기 저장 접두사는 그대로 두며 원본 서비스 저장 키를 읽지 않는다.

## 6. 과거 사실에서 현재 수리로의 순수 파생

각 방의 `instant`만 그 방의 추가 수리 하나를 만든다. `partial`과 `missing`은 서로
배타적인 공개 수리 하나를 만든다. 따라서 한 쌍의 파생 수리는 0–4개다.

```js
function deriveAddedRepairIds(config, pastChoices) {
  const ids = [];
  for (const room of config.rooms) {
    const id = config.instantRepairByChoice[pastChoices[room.choiceKey]];
    if (id) ids.push(id);
  }
  const disclosureId =
    config.disclosureRepairByChoice[pastChoices[config.disclosureKey]];
  if (disclosureId) ids.push(disclosureId);
  return [...new Set(ids)];
}
```

### 불변식

```text
필수 수리 = 기본 수리 정확히 3개
          + 과거 선택에서 파생한 중복 없는 추가 수리 0–4개

피날레 준비 = 필수 수리 전부 완료
```

- 모든 `manual + complete` fixture의 파생 수리는 `[]`다.
- 모든 방 `instant + missing` fixture의 파생 수리는 정확히 4개다.
- `partial`과 `missing` 파생은 동시에 생기지 않는다.
- 수리 순서는 자유이며 모든 방에서 중앙 공간으로 돌아갈 수 있다.
- 실제 시계·확률·네트워크와 무관하게 오프라인에서 같은 입력은 같은 수리를 만든다.
- 동의 확인이나 원 자료 확인이 불가능해도 새 재연·대체 자료·미확인 표시로 끝낼 수
  있다. 연락이 닿아야만 진행되는 경로는 없다.
- 과거 선택은 파도 내용과 추가 작업을 바꾸지만 raw damage, 탄속, 밀도, 피해 범위는
  바꾸지 않는다.

## 7. 복선과 정보 공개 예산

반전은 이미 본 장면의 의미를 바꾸되 과거 정답을 몰래 교체하지 않는다.

| 체크포인트 | 보여 주는 사실 | 아직 말하지 않는 것 |
|---|---|---|
| D-1 | 회색 관리자가 왼손으로 단말을 누름, 둥근 가방 잠금쇠 | 관리자 이름·동기·반디 정체 |
| D-3 | 이름이 닳은 관리 키, 같은 둥근 홈과 왼손 삽입 | 플레이어와 동일 인물이라는 확정 |
| D-5 | `다섯 설정 일괄 승인` 영수증, 현재 플레이어의 같은 카드 정렬 습관 | 서명 전체·기억 잠금 이유 |
| D-7 현재 감사 단말 | `[관리자 서명] <현재 슬롯 playerName>`, `과거 관리자는 나였다` | 선의의 동기·영이의 경고 전문·반디 정체 |
| D-10 현재 기록실 | `모두가 덜 힘들기를 바랐다`, 영이의 인간 최종 판단 경고, 고요의 비상 정지·실제 확산 차단 | 반디=영이의 완전 공개 |
| 파이널 시간순 복원 뒤 | 다섯 설정의 인과, 기록 잠금 책임, 반디가 영이의 다정한 페르소나였음 | 없음 |

### 반전 전 공정한 복선

최소 세 개가 아니라 다섯 층으로 배치한다.

1. 같은 왼손 단말 동작.
2. 회색 관리자와 현재 가방에 남은 같은 잠금쇠 자국.
3. D-3 키 홈과 가방 잠금쇠의 같은 둥근 규격.
4. D-5 플레이어가 카드를 실제 시간순 방향으로 먼저 정렬하려는 몸의 습관.
5. 고요 표식이 공격이 아니라 `기록 보존`, `확산 임계`, `비상 정지`를 계속 말함.

D-7 정체 공개는 공개 선택의 보상이 아니다. `audit_complete`, `audit_partial`,
`audit_missing` 모두 필요한 현재 수리를 마치면 같은 필수 감사 단말에 도달한다.

### 반디·영이·고요

- 반디는 노골적으로 거짓말하지 않는다. “내가 처음 본 것 같지 않아” 대신
  “이 자리는 처음인데, 네 손은 길을 아는 것 같아”처럼 관찰을 말한다.
- D-10에서는 반디의 말끝과 과거 영이 경고의 말끝이 같다는 마지막 복선만 준다.
- 파이널 전에는 `반디=영이`, 변신, 이름 교체를 보여 주지 않는다.
- 파이널 뒤에는 반디도 영이의 진짜 마음과 다정함의 일부였다고 명시한다.
- 고요는 피해 확산을 끊는 비상 정지 장치다. 검열자·가해자·파괴 대상으로
  단정하지 않는다.

## 8. 파이널 D-10→D-1 시간순 복원

다섯 쌍을 마치면 마음의 문에 사건 카드 다섯 장이 열린다. 게임은 자동으로
정렬하지 않는다.

### 입력

- 키보드: 방향키로 카드 이동, 확인으로 집기/놓기, 취소로 되돌리기.
- 게임패드: 방향 패드, 결정, 취소를 같은 의미로 사용.
- 터치: 44×44 이상 카드 손잡이와 `왼쪽`, `오른쪽`, `놓기`, `되돌리기` 버튼.
- 드래그만을 필수 입력으로 쓰지 않는다.

카드에는 날짜만 쓰지 않고 인과 단서를 함께 쓴다.

| 카드 | 앞면 단서 | 복원 뒤 사실 |
|---|---|---|
| `d10_judgment` | `결정을 덜 힘들게` | 인간 확인을 줄이는 최초 기본값을 승인함 |
| `d7_misinformation` | `빠른 도시 안내` | 출처·정정 창구가 약해지고 고요가 확산을 차단함 |
| `d5_recommendation` | `오래 머무는 길` | 인기와 체류 중심 추천이 다른 관점을 좁힘 |
| `d3_consent` | `닮은 방송` | 동의 범위와 합성 표시가 비어도 공개됨 |
| `d1_copyright` | `겹친 이름표` | 출처 빈칸이 쌓이고 플레이어가 기록을 잠금 |

정답은 `d10_judgment → d7_misinformation → d5_recommendation → d3_consent →
d1_copyright`다. 카드를 배치하거나 되돌릴 때마다 `finalTimelineDraft`를 저장한다.
오답 제출은 배열을 지우지 않고 `finalTimelineWrong`만 올린다. 두 번 틀리면 반디가
`무엇이 다음 설정을 가능하게 했는지 보자`라고 묻고, 세 번이면 날짜 테두리를
굵게 한다. 정답 제출 때만 `timelineRestored=true`가 된다.

### 복원 장면

정답 뒤에는 카드별 8–12초의 짧은 컬러 복원 장면을 실제 시간순으로 보여 준다.
장면은 건너뛸 수 있지만 `timelineRestored`와 해금 사실은 이미 원자 저장되어 있다.
마지막에 과거 관리자, 현재 플레이어, 영이, 반디, 고요의 역할을 한 화면에서
연결한다. 파괴 전투 대신 고요에게 앞으로의 확인 절차를 말하고 책임을 받아들이는
설득으로 넘어간다.

## 9. 네 엔딩 결정 규칙

새 캠페인은 기존 ID `home | silent | dawn | farewell`와 장면 정체성을 보존한다.
원래 모험의 `computeEnding()`은 변경하지 않고 새 캠페인에서만 `ending-rule-v1`을
사용한다.

### 쌍별 여정 프로필

세 방의 정규화 선택으로 `instantCount`를 계산하고 공개 모드를 함께 본다. 아래
첫 일치 규칙을 사용한다.

| 우선 | 조건 | profile | 여정 표 |
|---:|---|---|---|
| 1 | `disclosure=missing`이고 `instantCount>=1` | `repeat` | `silent +1` |
| 2 | 그 외 `instantCount>=2` | `depend` | `dawn +1` |
| 3 | 그 외 `disclosure=complete`이고 `instantCount=0` | `restore` | `home +1` |
| 4 | 나머지 | `mixed` | 표 없음 |

이 분류는 화면에 보이지 않는다. 일지에는 숫자나 프로필 대신 실제 선택과 수리
사실만 표시한다.

### 파이널 선택

| 파이널 선택 ID | 기존 엔딩 | 추가 표 | 장면 의미 |
|---|---|---:|---|
| `restore_together` | `home` | +2 | 기록을 함께 복원하고 다음 결정을 사람이 확인 |
| `reset_again` | `silent` | +2 | 책임을 피하려 다시 기억과 기록을 잠금 |
| `delegate_all` | `dawn` | +2 | 앞으로의 결정도 AI에 맡겨 편안함과 선택권을 맞바꿈 |
| `disconnect_all` | `farewell` | +2 | AI 연결을 모두 끊어 문제와 가능성을 함께 닫음 |

### 결정과 동률

1. 여정 표와 파이널 표를 더해 최고 후보를 찾는다.
2. 동률이면 여정 표가 더 많은 후보를 고른다.
3. 그래도 동률이고 파이널 대상이 후보에 있으면 파이널 대상을 고른다.
4. 그래도 동률이면 D-10→D-1 순서에서 먼저 만나는 결정적 pair profile 후보를
   고른다.
5. 손상된 미래 상태만을 위한 마지막 폴백은 `home → dawn → farewell → silent`다.

예시 A: 두 쌍이 `restore`이고 파이널에서 `reset_again`을 골랐다. `home` 여정 2,
`silent` 파이널 2로 동률이지만 여정 우선으로 `home`이다. 마지막 한 선택이 쌓인
두 사실을 뒤집지 않는다.

예시 B: 다섯 쌍이 모두 `mixed`면 여정 표가 없다. 파이널 선택이 플레이어가 지금
정리한 방향이므로 해당 후보가 이긴다.

예시 C: `restore` 1, `depend` 1, 나머지 `mixed`이고 `disconnect_all`이면
`farewell` 2가 최고다. 여정이 흩어진 상태에서 마지막 선택은 실제 결정력을 가진다.

`canonicalEndingBasis`에는 rule version, 다섯 profile, 각 `instantCount`와 공개 사실,
final choice, 후보 합계, tie-break reason만 저장한다. 숫자 합계는 UI에 노출하지
않는다.

## 10. canonicalEndingId와 시간선 실험실

다음 조건이 모두 참일 때만 엔딩을 한 번 계산한다.

```text
canonicalEndingId == null
AND 다섯 pair complete
AND timelineRestored == true
AND finalChoiceId가 네 고정 ID 중 하나
```

같은 원자 저장에서 `canonicalEndingId`, `canonicalEndingBasis`,
`timelineLabUnlocked=true`를 기록한다. 이후 원래 슬롯에서는 다시 계산하지 않는다.

### 시간선 실험실

첫 완료 뒤 마음의 문 메뉴에 `시간선 실험실`이 열린다. 이는 NG+가 아니며 원본
슬롯을 다른 경험으로 바꾸지 않는다.

- 원본 슬롯을 메모리 clone으로만 읽는다.
- 쌍 선택과 파이널 선택을 바꿔 결과 장면을 시험할 수 있다.
- `save`, `writeSlot`, 백업, 분석, PWA cache mutation을 호출하지 않는다.
- 새로고침·나가기에서 실험 상태를 폐기한다.
- 원본 `canonicalEndingId`, 사실 일지, pair state, draft, 지도·좌표를 쓰지 않는다.
- 실험 결과 화면에는 `첫 시간선은 바뀌지 않습니다`를 문자와 TTS로 알린다.

## 11. 화면·접근성·아동 안전

### 시간선 신호

| 신호 | 과거 | 현재 | 복원 뒤 |
|---|---|---|---|
| 팔레트 | 회색·낮은 채도 | 기존 컬러 | 현재 컬러+금색 사실선 |
| 테두리 | 끊긴 이중선 | 단단한 단선 | 이어진 이중선 |
| 표지 | `현재보다 N일 전 · 과거` | `현재 · 결과를 수리하는 중` | `실제 시간순 복원` |
| 소리 | 낮은 한 박자 | 원래 지역 테마 | 두 박자가 이어짐 |

색을 꺼도 표지와 테두리로, 소리를 꺼도 문자와 모양으로 구분한다. 전환은 450ms
색 복귀만 쓰며 흰 섬광·강한 글리치·화면 흔들림을 쓰지 않는다. `reduceFx`에서는
0ms 전환과 `[과거 종료]`, `[현재 시작]` 읽기를 사용한다.

### 공통 접근성

- 1280×800, 390×844, 844×390에서 대사·카드·버튼이 잘리지 않는다.
- 모든 터치 표적은 최소 44×44 CSS px다.
- 키보드·게임패드·터치가 같은 행동을 제공한다.
- TTS는 새 대사가 시작되면 이전 읽기를 중단하고, 파도 중 필수 정보는 짧은 문장과
  모양으로 함께 준다.
- `lowGraphics`에서는 배경 입자와 잔상을 끄되 충돌·사실 단서는 남긴다.
- 피날레 첫 파도는 무피해 연습이다. 실패 두 번 뒤 힌트, 세 번 뒤 느린 파도를
  제공한다.
- soft retry는 완료한 수리와 사실을 보존하고 해당 피날레 구간만 다시 시작한다.

### 아동 안전

- 모든 인물·초상·음성·기사·연락은 가상 고정 데이터다.
- 카메라, 마이크, 파일 선택, 클립보드, 자유 입력, 외부 메신저, 업로드를 쓰지
  않는다.
- 실제 친구 사진을 합성하거나 유포하는 조작을 플레이시키지 않는다.
- 위험한 과거 선택도 버튼으로 추상화하고 실제 도구명·절차·프롬프트를 보여 주지
  않는다.
- 플레이어를 악인이라 부르지 않는다. 편리함을 원한 선의와 확인을 줄인 책임을
  동시에 보여 준다.
- 공포·유혈·살인·복수·공개 망신을 사용하지 않는다.
- AI를 끄는 것만 정답으로 만들지 않고 도움을 받되 사람이 확인하는 경로를 둔다.

## 13. 405조합 검증과 증거

`405 = 5 × (3×3×3×3)`이다. 다섯 쌍 전체 선택의 직교곱이 아니라 각 쌍 81개를
다섯 번 전수하는 수다. 별도로 엔딩 규칙은 `4096 = 4^5 × 4` profile/final-choice
조합을 전수한다.

### 미래 구현의 405 수리 모델

```js
let caseCount = 0;
for (const config of pairConfigs) {
  for (const choices of enumerate3x3x3x3(config)) {
    const added = deriveAddedRepairIds(config, choices);
    assert.equal(new Set(added).size, added.length);
    assert.ok(added.length <= 4);
    assert.equal(config.baseRepairIds.length, 3);
    assert.ok(canReachFinale(config, choices, added));
    assert.deepEqual(projectFacts(config, choices), projectFacts(config, choices));
    caseCount += 1;
  }
}
assert.equal(caseCount, 405);
```

각 쌍에서 `all manual + complete`는 0개, `all instant + missing`은 정확히 4개다.
저장 roundtrip 전후 파생 집합이 같아야 한다. 기존 chapter·mercy·legacy record
fixture는 바뀌지 않아야 한다.

### 엔딩 4096 모델

다섯 pair profile의 `restore|repeat|depend|mixed` 조합 1024개와 파이널 선택 4개를
모두 계산한다. 모든 결과는 네 기존 ID 중 하나이고 결정적이어야 한다. 같은 결정적
profile이 두 쌍 이상이면 반대 파이널 2표가 그 합의를 뒤집지 못해야 한다.
`canonicalEndingId` freeze와 실험실 no-write는 별도 fixture로 검사한다.

## 15. 수락 조건

### 캠페인과 서사

1. D-1→D-3→D-5→D-7→D-10이 고정되고 쌍 안에는 허브 재진입이 없다.
2. 각 쌍은 30–40분 과거→같은 장소 현재→수리→장소형 피날레다.
3. 파이널은 플레이어가 D-10→D-7→D-5→D-3→D-1을 직접 배열한다.
4. D-7에서 모든 경로가 플레이어=과거 관리자 사실을 확인한다.
5. D-10에서 선의의 동기·영이 경고·고요 안전장치를 확인한다.
6. 반디=영이 완전 공개는 파이널 시간순 복원 뒤에만 있다.
7. 반전 전 재해석 가능한 복선이 최소 3개다.

### 선택·수리·엔딩

8. 각 쌍의 81조합은 기본 수리 3개와 파생 0–4개로 피날레에 도달한다.
9. 위험한 과거 선택은 시간을 실제로 줄이지만 전투 피해·속도를 올리지 않는다.
10. 대체 경로가 있어 연락·동의·원 자료 부재가 데드락을 만들지 않는다.
11. 엔딩은 기존 네 ID와 정체성을 유지한다.
12. 같은 여정 사실 두 개 이상은 반대 파이널 선택 하나에 뒤집히지 않는다.
13. 첫 `canonicalEndingId`는 한 번만 쓰이고 시간선 실험실이 덮지 않는다.

### 저장·접근성·안전·회귀

14. V10 원래 모험과 기존 메멘토 슬롯은 각각 `original`, `legacy-records`로 보존된다.
