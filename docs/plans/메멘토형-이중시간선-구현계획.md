# 메멘토형 이중 시간선 구현 계획

> **Wave 1 Task 1 문서 계약 (최신)**: 이 문서의 초기 V9·자동 복원·운영 저장소 가정은 아래 계약으로 대체한다. 구현은 이 계약과 기존 원본 흐름을 함께 만족해야 하며, 이 문서는 런타임 변경을 승인하는 문서가 아니다.

## Task 1에서 확정한 우선 계약

- 첫 타이틀 표면은 슬롯 선택 전 `routechoice`다. 라벨은 정확히 `원래 모험 시작`과 `메멘토 시간선 체험`이며, 선택 뒤 기존 **세 슬롯 → 이름 입력/이어하기** 흐름을 유지한다. 기존 슬롯을 골라도 리셋하지 않는다.
- `원래 모험 시작`은 기존 프롤로그·장 순서·보스·네 엔딩을 보존한다. `메멘토 시간선 체험`은 진입 직후 `reset_after` 첫 기록을 3,600 게임 프레임 및 실제 브라우저 시간 60초 이내에 보여 주는 가속 경로다. 가속은 연대기나 엔딩을 바꾸지 않는다.
- `MAP_PROPS.introlab`의 현재 시간 관리자 메모 `(18,16)`을 `admin-terminal`로 재사용한다. `reset_after`를 끝까지 확인한 `recordEvidence`가 없으면 `관리자 단말`은 잠김이다. 건너뛰기는 증거를 주지 않으며 모험 일지 다시보기로만 증거를 회복한다.
- 단말의 증거 비교 질문은 `손상된 기록과 비교하면, 이 안내문에서 지금 확인된 것은?`이며 정답은 `쓴 사람은 아직 확인할 수 없다`다. `영이가 코어를 망가뜨렸다`와 `반디의 말은 모두 정답이다`는 오답 예시다. OX식 교훈 퀴즈가 아니라 기록과 안내문을 대조한다.
- HUD는 `손상 기록 N/5` 대신 `현재 → 과거 ←` 라벨과 `1·2·3·5·7일 전` 표식을 가진 compact 역행 시간선(axis)을 쓴다. 색만으로 상태를 전달하지 않는다.
- 파이널은 다섯 카드를 오래된 순서(`first_approval → yeongi_warning → city_failure → reset_before → reset_after`)로 직접 놓는다. `남은 카드·배치됨·확인·오답·다시·결합` 상태를 제공하고 자동 정렬하지 않는다. `timelineOrderDraft`는 배치·되돌리기마다 저장하며 `timelineOrderWrong`은 비처벌 시도 횟수다. 정확히 확인했을 때만 `timelineMerged`가 된다.
- V10은 `storyRoute`, `recordEvidence`, `administratorTerminalSolved`, `timelineOrderDraft`, `timelineOrderWrong`을 정규화한다. V3→V9 체인, 세 슬롯, 기존 완료 세이브 호환은 유지한다. 저장·백업·캐시는 preview-only `fabletest2-memento-preview-*` 접두사와 `ai-ethics-adventure-memento-preview` 앱 ID만 사용하며 운영 `ai-ethics-adventure-*` 키를 읽거나 복사·삭제·fallback하지 않는다.
- 재개 행렬은 `!timelineMerged`이면 수동 카드 배치, `timelineMerged && !timelineRestored`이면 기존 복원된 색 요약, `timelineRestored && !bandiRevealed`이면 기존 반디 공개, 그 이후는 기존 영이 설득과 네 엔딩이다. `reduceFx`/`화면 효과 줄이기`에서는 새 전환을 0ms로 하고, 터치 표적은 44px 이상, `largeText`에서도 1280×800·390×844·844×390 안전 영역을 지킨다.

## 2. 실제 코드 흐름

- `src/game.js:newFlags()`가 슬롯에 저장되는 플랫 상태의 기본값을 만든다.
- `migrateSlotV3`~`migrateSlotV9`과 `loadSlot()`이 구세이브를 순차 변환한다. Task 1 이후 목표 `SAVE_VERSION`은 10이며 V10이 새 경로·증거·카드 상태를 정규화한다.
- `winChapterBoss(n)`이 장 클리어 플래그를 저장한 뒤 종료 대화를 연다.
- `openJournal`/`updateJournal`/`drawJournal`이 기존 모험 일지를 담당한다.
- `winGoyoBoss()`가 코어로 이동시키고, `finishShrine()`이 반디 정체 공개를 시작한다.
- `src/data.js:computeEnding(choiceKind, mercy)`가 `home`, `dawn`, `farewell`, `silent` 네 ID를 반환하고 `TRUE_ENDINGS`가 장면을 그린다.
- `syncSrLive()`가 대화와 알림을 DOM `aria-live` 영역에 미러한다.
- `sw.js`는 모든 경로를 상대경로로 프리캐시하며 `npm run bump`가 캐시 이름을 갱신한다.

## 4. 추가 상태 키

`newFlags()`에 다음 안전 기본값을 추가하고 슬롯 전체와 함께 저장한다.

| 키 | 형식 | 기본값 | 의미 |
|---|---|---|---|
| `damagedRecords` | 문자열 배열 | `[]` | 플레이어 공개 순서대로 해금된 기록 ID. 중복 없음 |
| `viewedRecords` | 객체 | `{}` | 끝까지 보거나 건너뛴 기록 ID별 완료 표식 |
| `skippedRecords` | 객체 | `{}` | 건너뛴 기록 ID별 표식. 다시보기 가능 |
| `pendingRecord` | 문자열 또는 `null` | `null` | 장 종료 뒤 아직 연출을 마치지 않은 기록 |
| `timelineMerged` | 불리언 | `false` | 코어에서 두 시간선 결합을 시작했는지 |
| `timelineRestored` | 불리언 | `false` | 실제 시간순 복원 장면을 완료하거나 건너뛰었는지 |
| `storyRoute` | 문자열 | `original` | `original` 또는 `memento` 진입 경로 |
| `recordEvidence` | 문자열 배열 | `[]` | 끝까지 확인해 증거가 된 기록 ID. 건너뛴 기록은 포함하지 않음 |
| `administratorTerminalSolved` | 불리언 | `false` | 현재 관리자 단말의 증거 비교를 정답으로 확인했는지 |
| `timelineOrderDraft` | 문자열 배열 | `[]` | 파이널에서 직접 배치 중인 카드 순서 |
| `timelineOrderWrong` | 정수 | `0` | 오답 제출 횟수. 비처벌성 안내용 |

일지 단계는 상태 키로 중복 저장하지 않는다. `damagedRecords.length`와 `timelineRestored`에서 순수 함수로 계산한다.

런타임 전용 `game.record`는 `{ ids, scene, page, ret, replay, restored, discovery?, onEnd }`를 가진다. 일반 기록은 `ids`에 한 ID를 넣고 `discovery`로 최초 발견 화면을 구분하며, 복원 화면은 실제 시간순 ID 배열과 `scene` 커서를 쓴다. 세이브에는 함수나 화면 커서를 넣지 않는다.

## 5. 세이브 V10 마이그레이션

1. 기존 `migrateSlotV3`~`migrateSlotV9`를 이름 변경 없이 유지하고 `migrateSlotV10(data)`를 V9 뒤에 추가한다.
2. 데이터나 `flags`가 없으면 기존 패턴처럼 그대로 반환한다.
3. 배열이 아닌 `damagedRecords`는 빈 배열로 정규화하고, 알려진 ID만 공개 순서대로 중복 없이 남긴다.
4. `viewedRecords`, `skippedRecords`가 일반 객체가 아니면 빈 객체를 넣는다.
5. `pendingRecord`가 알려진 ID가 아니면 `null`로 바꾼다.
6. `timelineMerged`, `timelineRestored`는 불리언으로 정규화한다.
7. 구세이브 기록 보충은 `chapter1Clear`~`chapter5Clear`만 신뢰한다. `defeated`는 일반 전투·도감 진행에도 쓰이므로 장 완료 근거로 사용하지 않는다.
8. 이미 클리어된 구세이브는 장 완료 플래그에 해당하는 기록을 `새 기록`으로 보충한다. `pendingRecord`는 만들지 않아 장면을 강제 재생하지 않고, HUD와 일지에서 직접 고르게 한다. 코어 완료 V9 세이브는 기존 완료 상태를 보존하기 위한 호환 표식만 유지하며, 새 플레이의 다섯 카드 수동 확인을 자동으로 완료시키지 않는다.
9. `storyRoute`는 `original`/`memento` 외에는 `original`로, `recordEvidence`는 알려진 ID의 고유 배열로, `administratorTerminalSolved`는 불리언으로, `timelineOrderDraft`는 알려진 ID의 고유 배열로, `timelineOrderWrong`은 0 이상의 정수로 정규화한다. 알 수 없는 미래 필드는 삭제하지 않는다.
10. V9 데이터를 preview prefix 아래에서 읽을 때 `storyRoute: "original"`을 기본으로 하고, `viewedRecords[id] && !skippedRecords[id]`에서 증거를 보충한다. 코어 완료 세이브의 기존 완료 상태는 보존하되 새 수동 배치를 강제하지 않는다.
11. `data.v = 10`, `SAVE_VERSION = 10`으로 올리고 `loadSlot()`의 마지막에 V10을 연결한다. V3→V9 마이그레이션은 그대로 실행한다.
12. `continueGame()`의 `Object.assign(newFlags(), loaded.flags)`가 누락 필드에 안전 기본값을 다시 제공하는지 회귀 테스트한다.

슬롯 3개, 삭제 취소, 백업·복원은 슬롯 JSON 전체를 보존하므로 구조를 바꾸지 않는다. preview-only 백업은 운영 앱 ID를 거부하고 preview prefix 외 키를 포함하지 않는다.

## 6. 테스트 우선 순서

### RED 1 — 데이터와 상태 경계

먼저 테스트에서 다음 공개 API 또는 테스트 seam을 요구하고 실패를 확인한다.

- 기록 공개 ID가 `reset_after → reset_before → city_failure → yeongi_warning → first_approval` 순서다.
- 실제 시간순 복원은 위 순서의 정확한 역순이다.
- 장 번호별 기록 해금이 한 번만 일어난다.
- 신규 세이브 기본값과 V9 fixture의 V10 마이그레이션이 존재한다.
- 일지 단계가 0/1, 2/3, 4/5, 복원 완료에서 요구 문구를 반환한다.

### RED 2 — 상호작용과 파이널

- 장 종료 뒤 `pendingRecord`가 설정되고 종료 대화 뒤 기록 모드가 열린다. 메멘토 진입은 첫 `reset_after` 기록까지 3,600 프레임/60초 이내다.
- X 건너뛰기 직전에 열람·건너뜀 상태가 저장되지만 `recordEvidence`는 저장되지 않는다. 일지 replay 뒤에만 증거가 생긴다.
- 일지 재열람은 해금·보상·진행을 중복 변경하지 않고 일지로 돌아온다.
- 봉헌 완료 뒤 다섯 카드를 수동으로 시간순 배치하고 정확히 확인한 뒤 기존 복원 요약과 반디 정체 공개로 이어진다.
- 복원 장면 건너뛰기도 파이널을 막지 않는다.

### RED 3 — 엔딩과 정체성 회귀

- 네 기존 엔딩 ID와 누적 `mercy` 조건이 남아 있다.
- `home`은 복원 완료와 높은 자비, `silent`는 낮은 자비, `dawn`은 의존 선택, `farewell`은 단절 선택을 구체 장면으로 보여 준다.
- 프롤로그부터 코어까지 맵·보스·챕터 순서가 보존된다.
- 화면 노출 문구에 사용 금지 어휘와 `-몬`식 새 명칭이 없다.
- 반디=영이, 고요의 비상 정지, 최소 세 개 공정한 복선이 데이터에 고정된다.

각 RED는 새 요구 기능 부재 때문에 실패해야 한다. 구 테스트를 약화하거나 삭제하지 않는다. 실패 로그는 `.orchestration/evidence/red/`에 남기고 GREEN 로그와 짝지어 보존한다.

## 8. 구현 세부

### 기록 데이터와 상태

- 데이터는 `src/data.js`에 표시 순서 배열 하나와 시간순 배열 하나로 둔다.
- 장 번호에서 기록 ID로 가는 매핑은 순수 함수로 제공한다.
- 해금 함수는 먼저 배열에 ID가 있는지 확인하고, 새 ID일 때만 `pendingRecord`를 설정·저장한다. 건너뛴 ID는 `recordEvidence`에 넣지 않으며 일지 다시보기 완료 때만 증거로 승격한다.

### 기록 연출

- 새 `record` 모드를 기존 update/draw 스위치에 추가한다.
- 최초 공개에서는 본문보다 먼저 `복원하기 | 나중에` 발견 선택을 보여 기록 획득을 장 종료 보상으로 인식하게 한다. `나중에`는 증거를 주지 않으며 일지 replay로 회복한다.
- Z/Enter/터치는 다음 페이지, X/Escape는 건너뛰기다.
- 완료 함수는 먼저 상태를 저장한 뒤 반환 모드와 콜백을 실행한다.
- `reduceFx`·`lowGraphics`에서는 즉시 표시한다. 다른 모드에서도 화면 흔들림과 전면 플래시는 쓰지 않는다.

### 일지

- 기록이 없을 때는 기존 학습 진척도 탭을 기본으로 유지하고, 기록이 하나라도 있으면 손상 기록 탭을 먼저 연다.
- 좌우 키로 `진척도`와 `손상된 기록`을 바꾼다.
- 기록이 없을 때는 초기 안내문의 현재 상태만 보여 준다.
- 기록 목록에서 Z를 누르면 재열람하고 완료 뒤 일지로 돌아온다.

### 파이널과 엔딩

- `finishShrine()`은 다섯 카드 수동 배치 화면을 시작한다. 정확한 제출 때만 `timelineMerged`를 저장하고 실제 시간순 복원 요약을 시작한다.
- 복원 완료 콜백에서 기존 반디 정체 공개 대화를 호출한다.
- `computeEnding()`의 ID와 기본 누적 자비 임계값은 유지한다. 선택 라벨과 장면을 복원·의존·단절 주제로 구체화한다.
- 엔딩 계산에는 여정 전체 `mercy`가 계속 필요하므로 마지막 선택 하나로 갑자기 바뀌지 않는다.

## 9. 검증 계획

### 자동 검증

```text
npm ci
npm run validate
npm test
npm run playtest
npm run test:browser
npm run pack
npm run bump
npm run validate
npm test
npm run playtest
npm run test:browser
npm run pack
```

`bump`는 JS·문서·PWA 자산 변경 뒤 실행한다. `pack` ZIP과 브라우저 스크린샷은 증거 경로에 복사할 필요가 있는 것만 보존하고 작업 트리 변경은 남기지 않는다.

### 실제 브라우저 시나리오

1. 첫 타이틀의 `routechoice`에서 `원래 모험 시작`/`메멘토 시간선 체험`을 고르고 세 슬롯으로 진입한다. 기존 슬롯 선택이 리셋되지 않는지 확인.
2. 메멘토 경로에서 `reset_after` 첫 기록이 3,600 프레임/60초 안에 열리는지 확인하고, 원래 경로의 기존 프롤로그와 장 순서를 확인.
3. 기록 2를 X로 건너뛰고 새로고침·이어하기 뒤 `recordEvidence`가 비어 있는지 확인.
4. 일지에서 기록 1과 건너뛴 기록 2를 다시 열고, 관리자 단말의 증거 비교 질문·정답·오답·잠김/준비/완료를 확인.
5. 기록 수에 따라 역행 시간선의 `1·2·3·5·7일 전`, `현재 → 과거 ←`, 다시보기 표식이 바뀌는지 확인.
6. 코어에서 다섯 카드를 자동 정렬 없이 직접 배치하고, 오답 뒤 draft 유지·다시·정답 결합 뒤 기존 복원 요약과 반디=영이 공개·영이 설득 진입을 확인.
7. 네 엔딩을 누적 자비·마지막 선택 조합별로 확인.
8. 기존 V8 슬롯 fixture를 브라우저 저장소에 넣고 오류 없이 이어하기.
9. 1280×800, 390×844, 844×390에서 기록·일지·단말·카드 텍스트와 터치 조작(44px 이상)이 겹치지 않는지 확인.
10. 큰 글씨, `reduceFx`/`화면 효과 줄이기`(0ms), 저사양, TTS/낭독기 미러, 서비스워커 업데이트, 오프라인 새로고침, 콘솔 오류 0 확인.

### 런타임 디버깅 감사 가설

최종 검증 때 최소 다음 세 가설을 실제 증거로 확인한다.

1. 장 종료 대화와 기록 콜백이 겹쳐 `pendingRecord`가 남는다.
2. 서비스워커가 예전 캐시를 보여 최신 기록 데이터가 로드되지 않는다.
3. 큰 글씨·모바일 가로에서 기록 조작 안내가 터치 패드와 겹친다.

## 10. 단계별 롤백

강제 reset이나 강제 push 없이 각 기능 커밋을 `git revert <commit>`로 되돌릴 수 있게 한다.

| 단계 | 롤백 단위 | 확인 |
|---|---|---|
| 설계 | 설계 문서 커밋 revert | 실행 코드·기준점 변화 없음 |
| RED 테스트 | 테스트 커밋 revert | 기존 테스트만 다시 통과 |
| 상태·데이터 | 상태 커밋 revert | `SAVE_VERSION`과 V10을 함께 되돌려 불완전 마이그레이션 방지 |
| 기록 UI | UI 커밋 revert | update/draw/input 모드와 일지 탭을 함께 제거 |
| 파이널·엔딩 | 파이널 커밋 revert | 기존 `finishShrine`, 네 엔딩 대사·조건으로 복귀 |
| PWA | bump 커밋 revert | package 버전과 SW 캐시 이름을 한 쌍으로 복귀 |
| 병합 뒤 | 미리보기 저장소 main에서 revert PR | 기준 태그·보관 브랜치는 그대로 보존 |

원본 저장소에서 문제를 해결하거나 원본 Pages를 건드리는 롤백은 어떤 경우에도 하지 않는다.
