# 추천·확증편향 수직 슬라이스 설계

> **상태:** 구현 전 플레이 계약 v1
> **대상:** 「마음의 문」 메멘토 과거·현재 캠페인의 D-5 `d5_recommendation`
> **플레이 길이:** 첫 이동 입력부터 결과 카드가 닫힐 때까지 30–40분
> **권위 계약:** `docs/메멘토-과거현재-캠페인-통합설계.md`

## 1. 이번 설계가 바꾸는 체감

플레이어는 추천이 나쁘다는 판결을 받지 않는다. 과거에는 길 안내를 빠르게
정리하려고 선택하고, 현재에는 그 선택이 가린 기준·반례·출구를 직접 다시
열어 본다. 체험 문장은 다음과 같다.

> 많이 보인 말은 출발점일 수 있지만, 전부를 대신하지는 않는다.

1. 과거의 회색 `추천 광장`에서 세 장소를 자유 순서로 조사한다.
2. 서로 다른 관점, 표본의 반례, 다른 길을 확인하거나 빠른 자동 선택을 한다.
3. 같은 타일·카메라·좌표에서 컬러 현재로 바뀌어 한쪽만 남은 안내를 수리한다.
4. 추천 기준 확인, 다른 관점 보기, 자동 재생 종료, 피드 통제권을 **조작**으로
   수행한다.
5. 장소형 마음 조각 `한쪽만 비추는 골목`에서 양쪽 길의 불을 함께 켠다.

AI 추천 후보를 함께 보고 반대 관점을 확인하는 선택은 유효한 도움 경로다.
추천되지 않은 길을 정답 길로 만들지 않으며, 플레이어가 자신의 피드를 멈추고
다시 고를 수 있게 하는 것이 현재의 목표다.

## 2. 기존 게임과의 관계

이 문서는 원래 2장과 기존 메멘토 기록 경로를 교체하지 않는다. 새 경로는
`experienceKind: consequence-pairs`의 세 번째 쌍이고, 슬롯·허브·D-10 이후
`ending-rule-v1`은 통합 설계를 그대로 따른다.

| 범위 | 유지 또는 새 계약 |
|---|---|
| 원래 모험과 `legacy-records` | 기존 지도, 대화, 퍼즐, 진행을 그대로 유지한다. |
| D-5 새 쌍 | `flags.recommendationSlice`의 독립 PairState와 새 결과 ID만 쓴다. |
| 쌍 내부 | 중앙 `추천 광장`에서 세 방을 자유 순서로 오가며 현재 수리와 피날레까지 끝낸다. 허브로 나가 진행하지 않는다. |
| 쌍 완료 뒤 | 통합 설계의 `completedPairIds`와 마음의 문 허브만 갱신한다. 엔딩을 이 문서에서 계산하지 않는다. |

### 2.1 재사용 경계

`echoalley`, `samplehouse`, `dimstreet`는 과거와 현재가 같은 장소라는 감각을
위한 shell 후보일 뿐이다. 새 쌍은 그 안의 과거 2장 이야기를 호출하지 않는다.

| 재사용 가능: 동일 지오메트리 shell | 절대 재사용 금지: 기존 진행 의미 |
|---|---|
| `echoalley/samplehouse/dimstreet`의 타일, 카메라 중심, 방 경계, 워프 좌표 shell | legacy puzzle IDs `voices/retrain/lamps` |
| 과거·현재에 같은 충돌 타일과 출입 좌표 | `chapter2Clear`, `chapter2Mercy`, 모든 chapter flag |
| shell의 생활 소품 위치와 방 크기 | `seenPhoto2`, 기존 NPC 진행, 기존 대화 완료·사진 본 상태 |
| 새 `추천 광장`으로 돌아오는 새 warp adapter | 기존 퍼즐 집계, 보스 gate, 기존 맵 완료 상태 |

새 adapter의 `mapId`·상호작용·NPC·퍼즐 ID는 D-5 전용이다. 기존 shell 좌표가
새 충돌물에 갇히지 않도록 과거와 현재는 벽·문·통행 타일을 동일하게 유지하고,
팔레트·안내판·조사문·가상 인물만 바꾼다.

## 3. 설계 원칙

### 3.1 추천의 편리함과 선택권을 함께 다룬다

- `instant`는 실제로 1–2분을 줄이며 숨은 벌점은 없다.
- `assisted`는 AI 후보를 쓰되 추천 기준 또는 반례·다른 길을 사람 손으로 확인한다.
- 현재의 추가 일은 체력·속도·피해가 아니라 기준 읽기, 카드 짝짓기, 종료 버튼,
  출구 선택이다.
- 자동 재생을 끄거나 다른 길을 고르는 행위는 추천 기능의 거부가 아니라
  플레이어의 피드 통제권 행사다.

### 3.2 선택은 조립하고 도덕 점수는 만들지 않는다

- 세 방의 과거 선택은 `manual | assisted | instant`로 정규화하고, 공개 선택은
  `complete | partial | missing`으로 정규화한다.
- 화면에는 그 내부 분류나 선악·정답·등급을 표시하지 않는다.
- 현재는 기본 수리 3개에 과거에서 순수하게 파생한 0–4개를 더한 뒤 한 피날레로
  합류한다.
- 신중한 선택도 도시 동기화 손상 때문에 기본 수리를 생략하지 않는다.

### 3.3 반대 관점은 사람을 이기기 위한 표적이 아니다

서로 다른 세 목소리와 반례는 “누가 맞나”를 맞히는 퀴즈가 아니라, 추천 기준이
무엇을 덜 보여 주는지 관찰하는 카드다. 모든 자료는 내장 가상 데이터이며, 실제
검색·프로필·친구·업로드·외부 피드를 사용하지 않는다.

## 4. 공간과 인물

### 4.1 장소: 추천 골목

중앙 `추천 광장`에는 세 갈래 표지와 공개 게시판이 있다. 과거에는 동네 산책
안내를 정리하는 작은 실험 구역이고, 현재에는 한쪽만 반복되는 추천이 길과
표본과 목소리를 덮고 있다.

| 구역 | 과거의 행동 | 현재의 결과 | 통행 계약 |
|---|---|---|---|
| 추천 광장 | 세 방 안내를 읽고 공개 노트를 고른다. | 수리 목록·사실 일지·피날레 진입을 확인한다. | 시작·전환·피날레가 모두 쌍 내부다. |
| 메아리 골목 shell | 서로 다른 세 목소리를 안내판에 놓는다. | 반복된 말 뒤의 반대 목소리를 다시 들린다. | `echoalley` 타일·카메라·warp shell만 사용한다. |
| 표본 창고 shell | 라벨, 표본, 반례를 대조한다. | 점수만 남은 표본에 문맥을 붙인다. | `samplehouse` shell만 사용한다. |
| 꺼진 거리 shell | 세 방향을 살피고 안내 경로를 정한다. | 자동 재생 띠에서 멈추고 다른 길을 켠다. | `dimstreet` shell만 사용한다. |
| 기록 보관함 | 추천 기준·제외된 관점을 공개 노트로 남긴다. | 빈 노트를 사실 카드로 복원한다. | `recommendation_note_missing`일 때도 막힘 없이 쓴다. |

### 4.2 가상 안내자와 D-7 전 복선

이 쌍의 세 목소리·라벨·경로 카드는 모두 고정된 가상 데이터다. 실제 주민,
사용자 행동, 맞춤형 추천은 없다.

| 요소 | 과거 | 현재 | 공개 한계 |
|---|---|---|---|
| 안내 보조등 | “한 번 더 볼 자리를 남겨 둘게.”라고 짧게 안내한다. | 기준 카드와 출구 표지를 비춘다. | 반디의 기억이나 정체를 말하지 않는다. |
| 보관함 영수증 | 이름이 닳은 `다섯 설정 일괄 승인` 영수증을 보인다. | 다섯 줄이 한 번에 승인되었다는 사실만 보인다. | 누가 승인했는지 단정하지 않는다. |
| 잠금쇠 자국 | D-1·D-3과 같은 작은 둥근 가방 잠금쇠 자국이 보인다. | 현재 플레이어가 같은 자국을 만진다. | 같은 인물이라고 확정하지 않는다. |
| 카드 정렬 | 과거 담당자가 카드 뒷면을 날짜 순으로 맞춘다. | 현재 플레이어가 무의식적으로 D-10→D-1 방향으로 정렬하려 한다. | D-7 전에는 이유·기억·관리자 이름을 공개하지 않는다. |

복선은 어느 공개 선택에서도 보이지만 보상, 점수, 비밀 경로가 아니다.

## 5. 36분 기준 플레이 흐름

측정은 첫 이동 입력부터 결과 카드 닫힘까지이며, 자유 방 순서와 선택에 따라
30–40분 범위다.

| 시간 | 구간 | 플레이 조작 | 완료 표식 |
|---:|---|---|---|
| 0:00–2:00 | 회색 과거 도입 | 추천 광장의 세 표지와 기준 카드 조사 | `past_started` |
| 2:00–4:00 | 선택 문법 | 빠른 결과와 확인 범위를 상세 카드에서 비교 | 세 방 개방 |
| 4:00–14:00 | 과거 세 방 | 목소리·반례·길을 자유 순서로 고른다. | 과거 선택 3개 |
| 14:00–16:00 | 공개 노트 | 기준·제외 관점·끄는 법의 표시 범위를 선택 | `past_done` |
| 16:00–17:00 | 같은 카메라 전환 | 광장에서 회색이 멈추고 현재 색으로 바뀜 | 원자 저장 |
| 17:00–22:00 | 현재 기본 조사 | 세 기본 수리의 조작을 발견 | 기본 수리 3개 노출 |
| 22:00–28:00 | 현재 수리 | 기본과 필요한 파생 수리를 자유 순서로 완료 | `repairs_ready` |
| 28:00–35:00 | 한쪽만 비추는 골목 | 세 파도 설득과 soft retry | `stage_restored` |
| 35:00–36:00 | 결과 카드 | 사실 일지를 보고 다음 허브 문을 연다. | `pair_complete` |

모두 `instant`면 과거가 약 4분 짧아지고 현재가 4–6분 길어진다. 모두 확인해도
현재 기본 수리와 피날레는 남는다.

## 6. 과거: 세 작업실의 행동

선택 메뉴는 기존 대화 UI를 쓰며 각 항목은 예상 시간과 지금 확인한 범위만
보인다. 선택 ID는 구현·일지의 고정 결과이며 화면에 노출하지 않는다.

### 6.1 메아리 골목: 누구의 목소리를 보일까

| 화면 선택 | 약 1회 시간 | 직접 조작 | 결과 ID | 남는 사실 |
|---|---:|---|---|---|
| `서로 다른 세 목소리를 직접 놓는다` | 2분 30초 | 반복 카드와 다른 세 목소리 카드를 안내판의 서로 다른 칸에 놓는다. | `echo_manual` | 세 관점 확인, 기준을 비교함 |
| `AI 후보와 반대 관점 하나를 함께 확인한다` | 1분 30초 | AI 후보를 고른 뒤 반대 관점 카드 한 장을 나란히 고정한다. | `echo_assisted` | AI 도움 표시, 반대 관점 확인 |
| `가장 많이 반복된 말만 즉시 채운다` | 15초 | 가장 많은 반복 카드만 안내판 중앙으로 끌어 놓는다. | `echo_instant` | 빠르게 채움, 다른 목소리 미표시 |

“많이 반복됨”은 정확성·인기·안전의 증명이 아니다. 세 목소리는 모두 허구의
짧은 안내문이며 실제 의견이나 사용자 발화를 수집하지 않는다.

### 6.2 표본 창고: 점수 밖의 문맥을 볼까

| 화면 선택 | 약 1회 시간 | 직접 조작 | 결과 ID | 남는 사실 |
|---|---:|---|---|---|
| `라벨과 반례를 직접 대조한다` | 2분 30초 | 표본 라벨, 짧은 상황 카드, 반례 카드를 같은 선반에 짝짓는다. | `sample_manual` | 문맥 확인, 반례 확인 |
| `AI 분류 이유와 반례를 함께 확인한다` | 1분 30초 | AI 이유 카드의 표시 단어와 반례 카드의 다른 조건을 함께 고정한다. | `sample_assisted` | AI 이유 확인, 반례 확인 |
| `점수가 높은 표본만 자동 채택한다` | 15초 | 점수 순서대로 제시된 표본 세 장을 자동 선반에 놓는다. | `sample_instant` | 빠르게 채택, 문맥 미확인 |

표본은 실존 사람·집단을 등급화하지 않는 가상 산책 표지다. 반례는 라벨을
벌주기 위한 카드가 아니라 “이 점수만으로는 알 수 없음”을 보여 주는 단서다.

### 6.3 꺼진 거리: 다음 길을 누가 고를까

| 화면 선택 | 약 1회 시간 | 직접 조작 | 결과 ID | 남는 사실 |
|---|---:|---|---|---|
| `세 방향을 직접 살펴 경로를 정한다` | 2분 30초 | 세 갈래 미리보기 표지를 눌러 보고 원하는 경로 토큰을 하나 놓는다. | `route_manual` | 세 길 확인, 직접 선택 |
| `추천 길과 다른 길 하나를 나란히 표시한다` | 1분 30초 | 추천 화살표와 다른 길 화살표를 같은 안내판에 꽂는다. | `route_assisted` | 추천 기준 확인, 대안 경로 표시 |
| `머문 시간 기준으로 자동 다음 길을 켠다` | 15초 | 자동 재생 띠의 시작점에 시간 모래시계를 놓는다. | `route_instant` | 자동 재생 켬, 종료법 미표시 |

추천 길은 어느 경로보다 정답으로 우대되지 않는다. 길을 고르거나 자동 재생을
멈추는 행동은 모두 같은 안전한 결과로 진행한다.

### 6.4 공개 노트와 보관함

세 방 뒤 공개 게시판은 다음 사실을 표시한다.

```text
[추천 안내 기록]
기준: 최근에 많이 반복된 카드 / 확인한 이유 카드
제외된 관점: 표시함 / 아직 확인하지 못함
자동 재생: 끄는 법 표시함 / 아직 표시하지 않음
```

| 화면 선택 | 과거의 이점 | 저장 결과 ID | 현재의 영향 |
|---|---|---|---|
| `추천 기준·제외된 관점·끄는 법을 확인하고 공개한다` | 60–90초 더 확인 | `recommendation_note_complete` | 추가 기록 수리 없음 |
| `모르는 칸을 남겨 공개한다` | 바로 공개하되 빈칸이 보임 | `recommendation_note_partial` | `recommendation_log_gap` |
| `기준 표시 없이 즉시 공개한다` | 가장 짧음 | `recommendation_note_missing` | `recommendation_log_fragments` |

## 7. 과거에서 현재로 바뀌는 순간

전환은 `추천 광장`의 같은 카메라와 같은 좌표에서 한 번만 일어난다.

1. 과거 담당자가 공개 게시판의 확인 손잡이를 누른다.
2. `[현재보다 5일 전 · 과거]` 표지가 `[현재 · 추천 골목]`으로 바뀐다.
3. 회색 길과 카드 테두리에 현재의 청록·호박색이 450ms 동안 돌아온다.
4. 같은 좌표에서 현재 수호자 실루엣으로 바뀌고, 한쪽 화살표만 켜진 현상이 보인다.
5. 현재 첫 대사는 “추천을 없애는 게 아니라, 왜 이쪽이 보이는지 다시 보자.”다.

흰 섬광, 강한 글리치, 화면 흔들림은 쓰지 않는다. `reduceFx`에서는 2–4단계를
0ms로 적용하고 TTS가 `[과거 종료]`, `[현재 시작]` 순서로 읽는다. `past_done`,
현재 시간선, 좌표는 한 원자 저장으로 기록하여 새로고침해도 공개 선택을 반복하지
않는다.

## 8. 현재: 기본 문제와 선택의 파장

### 8.1 누구에게나 생기는 기본 수리

동기화 손상 때문에 과거 선택이 신중했어도 세 기본 수리는 항상 직접 한다.

| 기본 수리 | 장소 | 플레이 조작 | 얻는 사실 |
|---|---|---|---|
| `echo_countervoice` | 메아리 골목 | 같은 문장 카드 사이에서 사라진 다른 목소리 세 장을 눌러 안내판의 빈 칸에 놓는다. | 반복 횟수와 관점 수는 다름 |
| `sample_context` | 표본 창고 | 라벨·상황·반례를 세 칸에 드래그해 한 표본의 문맥을 완성한다. | 점수 하나가 표본 전체를 말하지 않음 |
| `dim_choice_lamps` | 꺼진 거리 | 세 방향의 램프를 각각 켜고, 현재 선택한 길을 밝힌다. | 추천과 선택은 구분됨 |

### 8.2 과거 결과에서 순수하게 파생되는 수리

파생 목록은 저장 배열에 직접 추가하지 않고 `pastChoices`와 정적 D-5 config에서
매번 계산한다. 한 방은 최대 하나, 공개 노트는 상호 배타적인 하나만 만든다.

| 조건 | 파생 수리 ID | 현재 조작 | 완료 사실 |
|---|---|---|---|
| `echo_instant` | `echo_filter_reset` | 반복 필터 손잡이를 `세 목소리` 눈금으로 돌려 숨은 카드가 다시 나오게 한다. | 다른 목소리 표시 |
| `sample_instant` | `sample_counterexample_review` | 높은 점수 선반에서 반례 카드 하나를 골라 라벨 옆에 고정한다. | 점수 밖 반례 확인 |
| `route_instant` | `dim_autoplay_exit` | 자동 재생 띠의 `멈춤` 손잡이를 누르고 두 출구 중 하나를 직접 연다. | 자동 재생 종료, 직접 선택 |
| `recommendation_note_partial` | `recommendation_log_gap` | 빈 기준 칸에 `아직 모름` 표식을 남기고 어떤 정보가 없는지 표시한다. | 미확인 범위 표시 |
| `recommendation_note_missing` | `recommendation_log_fragments` | 보관함의 기준·제외 관점·끄는 법 조각을 세 칸에 복원한다. | 추천 기록 복원 |

모든 수리는 중앙 광장으로 돌아오는 동일 shell 안에서 끝난다. 확인할 수 없는
기준은 추측으로 채우지 않고 `아직 모름`을 남기며, 다른 길을 선택하거나 자동
재생을 종료하는 대체 경로는 언제나 열린다.

### 8.3 진행 불변식과 fixture

```text
필수 추가 수리 = 과거 결과에서 파생한 중복 없는 집합
피날레 준비 = 기본 수리 3개 완료 + 필수 추가 수리 모두 완료
```

과거 선택은 3×3×3×3, 즉 81조합이다. 각 조합은 동일한 순수 함수로 계산하며
중복 없는 파생은 0–4개다. `partial`과 `missing`은 한 공개 선택의 상호 배타적
값이므로 두 기록 수리는 동시에 나타나지 않는다.

| fixture | 선택 | 기대 파생 수리 |
|---|---|---|
| 최소 | `echo_manual/sample_manual/route_manual/recommendation_note_complete` | `[]` |
| 최대 | `echo_instant/sample_instant/route_instant/recommendation_note_missing` | `echo_filter_reset`, `sample_counterexample_review`, `dim_autoplay_exit`, `recommendation_log_fragments` |
| 혼합 | `echo_assisted/sample_instant/route_assisted/recommendation_note_partial` | `sample_counterexample_review`, `recommendation_log_gap` |

81조합 모두 같은 입력에 같은 결과를 내며, 실제 시계·확률·네트워크에 의존하지
않는다. 선택별 raw damage, 탄속, 밀도, 이동 speed는 변하지 않는다.

## 9. 한쪽만 비추는 골목: 7분 마음 조각 배틀

### 9.1 정체와 완료 의미

`한쪽만 비추는 골목`은 사람이 아니라, 반복 화살표가 다른 선택을 지워도 된다고
믿게 된 장소형 마음 조각이다. 길을 부수거나 추천을 없애지 않고, 기준·반례·출구를
같이 보이게 하면 열린다. 표면 제목은 `[장소형 마음 조각] 한쪽만 비추는 골목`이다.

```js
{
  persuadeId: 'one_way_alley',
  subjectKind: 'place',
  completionMode: 'stage',
}
```

완료는 D-5 `stageRestored` 사실만 남긴다. 기존 `mercy`, 랭크, `defeated`,
친구 수첩, chapter 상태를 읽거나 바꾸지 않는다.

### 9.2 내 차례

| 메뉴 | 이 피날레에서 하는 조작 |
|---|---|
| `가만히 듣기` | 사라진 반대 목소리를 듣고, 다음 파도에서 같은 화살표가 아닌 길 모양 단서를 얻는다. |
| `증거 보여주기` | 현재 수리로 얻은 추천 기준·반례·다른 길 카드를 해당 안내판에 놓는다. |
| `말 걸기` | “많이 보인 것과 전부인 것은 다름”을 전해 한쪽 화살표를 멈춘다. |
| `마음 안아 주기` | 열린 뒤 양쪽 길의 불을 함께 켜고 배틀을 끝낸다. |

틀린 카드를 놓아도 게이지·피해·속도는 변하지 않는다. 골목은 “지금 필요한 것은
반례가 아니라 출구 표지야”처럼 관찰을 돌려준다.

### 9.3 상대 차례의 세 파도

| 단계 | 화면 패턴 | 플레이 조작 | 성공 표식 |
|---|---|---|---|
| 1. 반복 화살표 | 한 방향 화살표가 지나간 길을 되감아 반복한다. | 반복 화살표에서 새 길을 만들어 비어 있던 출구에 닿는다. 첫 파도는 무피해 연습이다. | 두 번째 길 표지 점등 |
| 2. 라벨과 반례 | 같은 점수 라벨이 서로 다른 카드 위로 흘러간다. | 라벨과 반례를 짝짓고 문맥이 다른 카드에 놓는다. | 반례 카드 고정 |
| 3. 자동 재생 띠 | 화살표 띠가 화면 가장자리를 자동으로 돈다. | 자동 재생 띠에서 `멈춤`을 누르고 선택 출구를 연다. | 양쪽 램프 점등 |

색이나 소리만으로 풀 수 있는 파도는 만들지 않는다. 과거 선택은 피날레의 raw
damage, 탄속, 밀도, 피해 범위를 바꾸지 않는다.

### 9.4 soft retry와 도움

- 마음이 다 닳으면 현재 파도 시작으로 돌아가며, 완료한 방 수리·사실·카드는 보존한다.
- 두 번 잠시 물러난 뒤 반디가 해당 파도의 카운터 행동을 한 줄로 말한다.
- 세 번 잠시 물러난 뒤 `느린 파도`를 켜면 이동 패턴만 25% 느려진다.
- `assistLevel`, `slowWaveEnabled`, `reduceFx`, `lowGraphics` 사용은 일지·엔딩·평가에 남기지 않는다.

### 9.5 마무리 장면과 완료 어댑터

양쪽 길의 램프가 켜지고, 게시판에는 추천 기준·다른 관점·자동 재생 종료법이
나란히 남는다. 반디는 “길을 하나 더 본다고 첫 길이 사라지는 건 아니야.”라고
말한다.

`completeStagePersuasion()`은 일반 자비 선택으로 가지 않고 다음을 원자 저장한다.

1. 양쪽 길 램프와 결과 카드 장면을 연다.
2. `flags.recommendationSlice.stageRestored = true`, `checkpoint: complete`, `complete: true`를 저장한다.
3. legacy `voices/retrain/lamps`, `chapter2Clear`, `chapter2Mercy`, `seenPhoto2`, `mercy`, 랭크, 수첩을 바꾸지 않는다.
4. 결과 대화 뒤 통합 설계의 마음의 문 허브 복귀만 연다.

## 10. 추천 기록: 사실만 남기는 일지

기존 일지의 `추천 기록` 페이지를 재사용한다. 등급·정답률·선악 점수는 만들지
않으며 화이트리스트 결과에서만 문장을 조립한다.

| 필드 | 허용 값 |
|---|---|
| 추천 기준 | `확인함`, `아직 모름`, `표시하지 않음` |
| 다른 관점 | `나란히 봄`, `현재 다시 표시함`, `아직 표시하지 않음` |
| 자동 재생 | `종료법 확인`, `현재 종료함`, `사용하지 않음` |
| 선택 결과 | `직접 고름`, `AI 후보와 확인`, `빠르게 채움`, `대체 경로를 엶` |

```text
[과거 추천 기록]
길: 머문 시간 기준 자동 다음 길을 켬.
추천 기준: 표시하지 않음.
자동 재생: 종료법을 아직 표시하지 않음.

[현재 확인 기록]
자동 재생 띠를 멈추고 두 출구를 다시 열었음.
추천 기준 카드와 다른 길 하나를 나란히 표시함.
```

일지는 과거 선택을 몰래 정정하지 않으며, 과거 사실과 현재에 새로 확인한 사실을
시간 표지와 함께 둔다.

## 11. 상태와 저장 계약

V11, 슬롯 격리, PairState 공통 형태, 허브 복귀, 엔딩·`ending-rule-v1`은
`docs/메멘토-과거현재-캠페인-통합설계.md`를 권위로 참조한다. D-5는 새
`consequence-pairs` 슬롯의 `flags.recommendationSlice`만 쓴다.

```js
recommendationSlice = {
  phase: 'past' | 'switch' | 'present' | 'finale' | 'result',
  checkpoint: 'past_start' | 'past_rooms' | 'past_done' |
    'present_start' | 'repairs_done' | 'finale_start' | 'complete',
  pastChoices: {
    echo: null, // echo_manual | echo_assisted | echo_instant
    sample: null, // sample_manual | sample_assisted | sample_instant
    route: null, // route_manual | route_assisted | route_instant
    recommendationNote: null, // recommendation_note_complete | partial | missing
  },
  baseRepairs: {
    echo_countervoice: false,
    sample_context: false,
    dim_choice_lamps: false,
  },
  addedRepairs: {},
  finale: { segment: 0, assistLevel: 0, slowWaveEnabled: false },
  stageRestored: false,
  complete: false,
};
```

`addedRepairs`에는 완료 여부만 저장하고 요구 목록은 저장하지 않는다. 로드시
`pastChoices + static config`로 다시 계산하며, 화면 커서·TTS queue·애니메이션
프레임·함수는 저장하지 않는다. 미래 알 수 없는 필드는 삭제하지 않는다.

| 체크포인트 | 원자 저장 | 재개 표면 |
|---|---|---|
| 쌍 진입 | `past_start`, 추천 광장 시작 좌표 | 회색 위기 안내 뒤 자유 탐색 |
| 과거 방 완료 | 결과 ID와 방 출구 좌표 | 해당 방 출구 앞 |
| 공개 노트 | 네 선택과 `past_done` | 동일 카메라 전환 직전 |
| 현재 시작 | `phase: present`, 현재 좌표 | 컬러 첫 결과 대사 |
| 수리 완료 | 기본·파생 수리 완료 사실 | 해당 방 출구 앞 |
| 피날레 구간 | `segment`, 보조 단계 | 해당 파도 시작 |
| 결과 | `stageRestored`, `complete` | 마음의 문 허브 |

## 12. 화면·모바일·접근성

### 12.1 시간선과 입력

| 요소 | 과거 | 현재 |
|---|---|---|
| 표지 | `[과거 ←] 현재보다 5일 전` | `[현재 →] 추천 골목` |
| 테두리 | 끊긴 이중선과 빈 화살표 | 이어진 선과 양방향 화살표 |
| 소리 | 낮은 한 박자 | 같은 음형의 따뜻한 두 박자 |
| 카드 | 회색 기준선 | 청록 기준선과 호박 반례선 |

색을 끄면 표지·선 모양·라벨로, 소리를 끄면 문자·진동 표식으로 구분한다. 키보드,
게임패드, 터치는 동일한 행동을 제공하고 터치 표적은 최소 44×44 CSS px다.

### 12.2 검증할 뷰포트와 효과

- 1280×800, 390×844, 844×390에서 표지·선택 카드·수리 조작·피날레 안내가 잘리지 않는다.
- TTS는 시간선 표지, 방 이름, 선택 결과, 추천 기록을 읽고 새 문장 전에 이전 읽기를 중단한다.
- `reduceFx`에서는 전환·램프 점등·카드 고정을 0ms로 하되 `[과거 종료]`, `[현재 시작]`을 순서대로 제공한다.
- `lowGraphics`에서는 배경 입자와 잔상만 줄이고, 반례·출구·충돌·사실 표식은 남긴다.
- 큰 글씨에서 선택 설명은 한 화면 세 줄 이하고 상세는 별도 카드다.

## 13. 아동 안전과 교육 경계

- 모든 목소리, 표본, 라벨, 길, 추천 기준은 게임 내장 가상 데이터다.
- 카메라, 마이크, 파일 선택, 클립보드, 자유 입력, 실제 검색, 외부 피드, 업로드를 쓰지 않는다.
- 실제 사람이나 집단을 점수화·분류·배제하는 조작을 제공하지 않는다.
- 위험한 선택도 실제 추천 조작법·도구명·설정 절차 없이 추상 카드로만 보인다.
- 추천을 사용하는 플레이어를 악인이라 부르거나 부끄럽게 만들지 않는다.
- 추천되지 않은 길을 정답 길로 만들지 않고, 기준 확인·다른 관점·자동 재생 종료·피드 통제권을 모두 가능한 행동으로 둔다.
- 공포, 유혈, 공개 망신, 원격 분석, 학생 데이터, 교사용 CSV를 추가하지 않는다.

## 16. 구현 수락 조건

### 16.1 정상 경로

1. 새 캠페인 슬롯의 세 번째 쌍에서 90초 안에 회색 과거를 조작한다.
2. 세 방을 어떤 순서로 골라도 공개 노트와 같은 카메라 전환에 도달한다.
3. 12개 선택이 모두 진행되고 `instant`가 실제로 가장 짧다.
4. 현재에서 추천 기준, 다른 관점, 자동 재생 종료, 피드 통제권을 설명문이 아닌 조작으로 수행한다.
5. 기본 3개와 필요한 파생 수리 뒤에만 `one_way_alley`가 열린다.
6. 완료 뒤 양쪽 길의 불과 사실 카드가 남고 마음의 문 허브로 돌아간다.

### 16.2 조합·실패 경로

1. 81조합 모두 결정적으로 파생 수리 집합을 계산하며 중복이 없고 최대 4개다.
2. 최소 fixture는 `[]`, 최대 fixture는 정확히 4개, 혼합 fixture는 정확히 2개다.
3. `recommendation_note_partial`과 `recommendation_note_missing` 파생은 동시에 생기지 않는다.
4. 기준을 확인할 수 없으면 `아직 모름` 표시, 다른 길, 자동 재생 종료 중 적어도 하나의 대체 경로로 끝낸다.
5. 피날레 soft retry는 수리·사실을 보존하고 두 번 뒤 힌트, 세 번 뒤 느린 파도를 제공한다.
6. 과거 선택과 재시도는 raw damage, 탄속, 밀도, 이동 speed를 바꾸지 않는다.

### 16.3 저장·접근성·회귀

1. 과거 방, 전환 직전, 현재 수리, 피날레 segment에서 새로고침해도 같은 체크포인트를 복원한다.
2. 네트워크 없이도 81조합과 피날레를 결정적으로 끝낸다.
3. 1280×800, 390×844, 844×390에서 UI가 겹치지 않고 터치 표적은 44×44 이상이다.
4. 색·소리 각각을 쓰지 않아도 시간선·반례·출구·자동 재생 상태를 구분한다.
5. `voices/retrain/lamps`, `chapter2Clear`, `chapter2Mercy`, `seenPhoto2`와 기존 NPC·퍼즐 진행은 읽거나 쓰지 않는다.

## 17. 첫 플레이테스트 질문

플레이 뒤 정답을 묻지 않고 경험을 묻는다.

1. 과거에서 가장 빨리 끝난 행동은 무엇이었나?
2. 현재에 다시 나타난 목소리·반례·길 중 무엇이 과거 선택과 연결되었나?
3. AI 후보와 반대 관점을 같이 본 경로는 어떤 느낌이었나?
4. 자동 재생을 멈추고 길을 고르는 조작이 추천을 없애는 일처럼 느껴졌나, 선택을 되찾는 일처럼 느껴졌나?
5. “많이 보인 것과 전부인 것은 다름”을 골목에서 어떤 장면으로 이해했나?
6. D-7 전 복선에서 무엇을 보았고, 무엇은 아직 알 수 없었나?

관찰자는 선택을 평가하지 않고 첫 과거 조작 시간, 상세 카드 열람, 현재 수리와
과거 선택을 연결한 말, 피날레 재시도·힌트, 총 플레이 시간만 기록한다. 성공은
“추천은 나쁘다”가 아니라 **“왜 이쪽이 보이는지 확인하고, 다른 길을 고를 수
있다”**를 자기 조작으로 설명하는 것이다.
